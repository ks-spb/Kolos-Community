# Glaz: один терминал и два рабочих экрана

## Реализованный план
1. Вынести единственный терминал из панели элементов в постоянную нижнюю область.
2. Переключать только верхний вид: «Пики и элементы» / «Нейроны».
3. Использовать снимки текущего States-подпроцесса, а не отдельную модель опыта.
4. Читать и проецировать снимки вне Tk-потока. Рисовать Canvas в Tk-потоке.
5. Разделить A/C, I/S, структурные связи, реальные flow и члены уравнений.
6. Проверить переключение без остановки/перезапуска ядра, сохранение ввода,
   продолжение захвата и распознавания, независимую заморозку рисунка.

## Запуск
Обновите проект из feature/browser-graph-lab. Новый просмотр не требует новых
зависимостей сверх уже установленных requirements-states.txt. run_main.bat не менялся.

1. Запустите run_main.bat, выберите «Состояния и цели (ПК)».
2. Выберите монитор и включите захват. Обучайте обычным способом:
   команда → 3 → показ с ожиданием наблюдений → Esc → 5 → 1.
3. Сверху выберите «Нейроны». Терминал останется снизу.
4. Введите обученную команду либо задайте образ через меню «Опыты и инструменты».
5. Наблюдайте текущий граф. Возврат на «Пики и элементы» не отменяет попытку,
   не перезапускает процесс, не выключает захват и не очищает строку ввода.

Во время обучения новые долговременные вершины появляются после сохранения и
подтверждения показа. Запись событий мыши сама по себе не считается нейронным обучением.

## Управление
Клик на вершину/связь — ID, каналы, порог, вес, зарегистрированная передача и
эффективный вклад. Колесо — масштаб, перетаскивание фона — сдвиг, «Вписать» — обзор.
Слои/поиск/фильтр активных меняют рисунок, не рабочую память. На рисунке не более
300 вершин одновременно; явный счётчик показывает усечение. Узлы не удаляются.

«Заморозить рисунок» останавливает только показ. Само ядро останавливают «Пауза»
в терминале / F9. Снятие галочки возвращает к последнему снимку, не исполняет его.
Старый браузерный просмотр сохранён в «Опыты и инструменты → Нейроны в браузере».

## Что означает «в реальном времени»
Проверка новых данных каждые 100 мс; обработка файлов идёт в одном фоновом потоке.
Это целевой интервал опроса, не гарантированная задержка. Если расчёт/диск занят,
показывается последний готовый снимок, а пропущенные снимки явно подсчитываются.
Сетевых запросов, WebView, Node или браузера для встроенного Canvas нет.

Вид не вызывает tick/learn/start/motor. Накопление/затухание берутся из снимков.
Частицы иллюстрируют вычисленный вклад; они не влияют на выбор. Пунктирные order
связи образа не получают выдуманных импульсов. I не заменяет внешний S.

При скрытии пиков работают захват, детектор, подписи лупы и контроль подтверждений.
Отключается только отрисовка пиков. Проверка наведения использует исходные
координаты и не требует размеров скрытого canvas.

Просмотр доступен для States. Legacy v4 не публикует такой формат снимков:
показывается объяснение, а не чужой граф. Смена движка очищает последний снимок.

## Данные и границы
Снимки содержат команды и читаемый текст полей. Они остаются в существующей
папке текущего IPC-сеанса ~/.kolos/states-ipc; кольцо ограничено 80 снимками.
Память алгоритма и legacy-базы не мигрируются и не перезаписываются.
Просмотр включается явно. Включение/выключение браузерного просмотрщика не
отключает встроенный: у них отдельные маркеры наблюдения.

Одно окно Glaz по-прежнему закрывает то, что расположено под ним на мониторе.
Расположите целевое приложение рядом или на другом мониторе. Наличие нейронного
экрана не делает скрытые реальные иконки видимыми для Glaz.

## Проверки
python -m unittest discover -s tests/desktop -v
KOLOS_INLINE_GUI_SMOKE=1: реальные Tk-виджеты, моделируемая граница захвата/мыши.
Windows smoke дополнительно запускает реальный подпроцесс Kolos внутри Glaz,
переключает рабочие экраны, получает его снимок; отдельная проверка реального
Win32-поля сохранена. Это не подтверждение всех сценариев в приложениях пользователя.
