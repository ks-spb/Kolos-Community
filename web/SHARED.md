# Один граф, двенадцать опытов — общая память Kolos

## Что проверяется

Все двенадцать ранее созданных возможностей должны работать не только на
индивидуальных маленьких графах. Один экземпляр States получает всю учебную
память до первого контрольного запроса. Затем тесты 1–12 запускаются на нём
последовательно. Долговременные вершины, связи, веса, команды, языковые пары и
общие коэффициенты между тестами не меняются.

Прежние изолированные проверки остаются: они полезны для локализации ошибок.
Новый обязательный набор проверяет интерференцию — помехи от соседних знаний.
Это не проверка двенадцати одновременно исполняемых независимых задач.

## План и реализация

1. Создать один согласованный виртуальный мир и набор независимых демонстраций.
   Не конкатенировать готовые ID из разных графов: обучить один движок один раз.
2. Переиспользовать реально одинаковые наблюдаемые состояния, символы и моторные
   соответствия. Отличающийся контекст описывать видимыми признаками, не номером теста.
3. Проверить наивное объединение прежней математикой и зафиксировать ошибки.
4. Устранить потерю полезного сигнала единым оператором конкуренции входов.
   Не снижать пороги/менять веса для конкретного контрольного случая.
5. Прогнать все 12 на одной памяти в прямом, обратном и смешанном порядке;
   проверить восстановление из сохранённой базы и перенос между группами знаний.
6. Показывать эту же рабочую сеть существующим NeuronView: I/S, A/C, состояния,
   входные вхождения, торможение, реальные event.flows и эффективные вклады.

## Состав одной учебной базы

В базовом учебном наборе 18 независимых моторных демонстраций, один прежний ввод
`5432` и шесть пар языка/образа. Они создают 360 вершин опыта и 102 языковые вершины,
428 связей опыта и 85 языковых связей. Представления текущей цели и рабочие
вхождения временные; они не входят в эти счётчики долговременной памяти.

Одна демонстрация `добавь траты 1700`; значения 2345/1354 не превращаются в
обученные моторные сценарии. Для языка сохраняются прежние пары с 1700/2345,
но контрольная фраза с 1354 отсутствует в обучении.

Все поверхности принадлежат одному миру: рабочий стол, перекрывающее окно,
калькулятор, архивная/новая панели, общий обход, общий результат, ошибочный исход
и четыре уровня. С рабочего стола есть изученные входы в панели и уровни; с
результата/последнего уровня есть изученный HOME. Поэтому это не просто двенадцать
изолированных графов, записанных в один файл.

### Почему две панели

В старом тесте 6 FAST был слабым (0,35), а в тесте 10 — сильным (0,9). Одной и той
же связи невозможно одновременно присвоить оба веса без противоречия.
В общем мире есть два различимых наблюдения: на архивной панели виден ARCHIVE,
на новой — CURRENT. Кнопки FAST/VIA остаются теми же символическими объектами.
Контекстные переходы различаются исходным наблюдением. NEXT, конечный результат,
HOME и остальной рабочий стол действительно общие.

Веса устанавливаются только при создании учебной базы и остаются неизменными
во всех контрольных запусках. Номер теста никогда не передаётся в ядро.

## Выявленная помеха и изменение математики

На одной базе прежнее усреднение проходит 7 из 12 сценариев. Тесты 5, 7, 9, 11 и
12 блокируются: полезное возбуждение рабочего стола размывается дополнительными
изученными переходами. Это воспроизводится командой контрольного набора, а не
выводится только из одного скриншота.

Переходы, ведущие к разным результатам, — альтернативы, а не обязательные части
одного составного признака. Для входов вершины состояния теперь применяется
конкуренция сильнейших взвешенных сигналов:

```
x_j = A_j × вес_j
D_mean = sum(x_j) / число_входов
D_competitive = max(x_j)
D = (1 − stateCompetition) × D_mean + stateCompetition × D_competitive
A' = clip(decay × A + (1 − decay) × D)
```

Общий `stateCompetition = 1` одинаков для всех задач. `0` — воспроизводимый
контроль со старым усреднением, не автоматический запасной алгоритм. На входах
вершин переходов остаётся прежняя схема. Равные максимальные вклады разделяют
поддержку без выбора по ID; выбор реального действия по-прежнему требует
достаточного сигнала, порога, отрыва от конкурента, наблюдаемой допустимости и
отсутствия refractory-запрета.

Это инженерный оператор конкуренции/максимального объединения в нейроноподобной
сети, не утверждение о точной биологической реализации. Здесь нет BFS/A*, таблицы
готовых решений, новой LLM или удаления не относящейся к задаче памяти.

`backward.mjs` / `backward.py` используются и обычным восстановлением команды,
и сетью целей. Изменение не ограничено тестовым стендом. Изображение и язык
сохраняют прежнюю математику. Старый отдельный Legacy `main.py` не изменён.

В event.flows записаны и сырое возбуждение, и `term` — полезный вклад после
конкуренции и утечки. Инспектор не восстанавливает старое усреднение поверх нового
оператора. Непобедивший вход может иметь ненулевой сырой сигнал, но нулевой term.

## Общие сценарии

| № | Начальный запрос/наблюдение | Критерий |
|---|---|---|
| 1 | Рабочий стол, `открой окно` | A → Enter → окно |
| 2 | Окно, `закрой окно` | X → рабочий стол |
| 3 | Окно, `открой окно` | X → A → Enter; нет показа всей цепочки |
| 4 | Рабочий стол, `добавь траты 2345` | CALC → 2345 |
| 5 | Рабочий стол; окно, затем поле=3521 | A → Enter → X → CALC → 3521 |
| 6 | Архивная панель, цель=общий результат | VIA → NEXT при слабом FAST |
| 7 | Цель=2345; после CALC появляется помеха | CALC → X → CALC → 2345 |
| 8 | Уровень 0, цель=уровень 3 | GO0 → GO1 → GO2 |
| 9 | Перекрывающее окно, цель=2345 | X → CALC → 2345 |
| 10 | Новая панель; FAST неожиданно ведёт не туда | FAST → RETURN → VIA → NEXT; один след ошибки |
| 11 | Образ=2345 при перекрывающем окне | I без действий → затухание → X/CALC/2345 → S |
| 12 | `я хочу увидеть 1354 в поле` | языковой опыт → I без действий → X/CALC/1354 → S |

Стенд задаёт начальные условия между независимыми тестами и две явные внешние
помехи (7/10), но не вмешивается в выбор дальнейших действий. Рабочая цель,
вхождения и временные активации начинают новую попытку. Знания не перезагружаются.

Дополнительный сквозной опыт: из уровня 0 заданы результаты «уровень 3» и
«FIELD=4512». В одной попытке, без перестановки среды внутри решения, сеть
выполняет GO0 → GO1 → GO2 → HOME → CALC → 4512. Полную цепочку не показывали.

## Запуск и визуализация

`npm run build` создаёт `web/dist/shared.html`. Это автономный HTML, который
можно открыть в браузере. Вверху — неизменная база и её короткая контрольная метка.
Метка предназначена для удобства, не для криптографической защиты. Приёмка
сравнивает полную сериализацию памяти, отчёт дополнительно содержит SHA256.

- «Смотреть тест» / «Один такт» — текущий эксперимент; интервал регулируется.
- «Смотреть 1–12» — последовательный показ на одной базе.
- «Проверить все» — ускоренный расчёт всех двенадцати на текущем экземпляре.
- «Запись» в строке результата — снимки именно его выполненных расчётов.
- «Вся память» — включая узлы остальных задач, до 1000 видимых узлов (учебная база
  умещается). Другие слои/фильтры меняют только рисунок, не сеть.
- Экспорт/импорт — общая база знаний без возобновления старого действия. Сохранение
  в localStorage при доступности браузерного хранилища; экспорт остаётся доступным
  при запрете хранилища. После перезагрузки старые PASS не выдаются за новый прогон.

В Glaz: `run_main.bat` → «Состояния и цели (ПК)» → «Общая учебная база · 12 опытов».
Это отдельный безопасный учебный стенд, не замена реальной пользовательской памяти.
`/sharedtest` в терминале или `python -m kolos_states.shared_experiment` запускают
те же двенадцать на одной Python-базе, без мыши и клавиатуры Windows.

## Обязательная приёмка

```
cd web
npm run test:shared
npm run test:shared:browser
# из корня проекта
python -m unittest discover -s tests/desktop -p test_shared.py -v
python -m kolos_states.shared_experiment --evidence tests/desktop-output/shared
```

Полная приёмка 1–12 дополнена общим набором. Проверяются прямой/обратный/смешанный
порядки, перемешанный порядок обучения, неизменность памяти, старый mean-контроль,
обнуление нужной связи, отказ при неоднозначном обучении/неизвестном тексте,
восстановление базы, точные вклады визуализации и сравнение Python/JS по каждому
шагу всех двенадцати. Browser test дополнительно проверяет историю без исполнения,
полную видимость базы, сквозной опыт, перезагрузку и мобильную ширину.

## Что этот результат не доказывает

Это не гарантия для произвольного объединения любой памяти. Неоднозначные команды
и неразличимые состояния не получают скрытого правильного ответа. Неизвестные
формулировки/клавиши не становятся известными. Реальное восприятие Glaz не улучшено:
нужны читаемые поля и надёжно распознаваемые иконки. Старая SQLite-база не мигрируется.
Все двенадцать одновременно на реальном ПК не исполнялись. Базовые самостоятельные
тесты по-прежнему обязательны вместе с новым общим набором.
