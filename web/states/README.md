# Kolos: состояния и цели — четвёртый изолированный режим

Основа: `feature/browser-graph-lab` @ `8f8433fd8c3e672c49f51f09282f7403997f6557`.
Существующие три движка сохраняются. Сборка добавляет четвёртую
панель в тот же автономный HTML. Доступен запуск из `file://` и с GitHub Pages.

## Четыре обязательных опыта

1. Рабочий стол: распознать A, переместить курсор, проверить A, кликнуть, нажать
   Enter. Клик лишь выделяет A; именно Enter открывает непрозрачное окно.
2. Окно: распознать и проверить X, кликнуть. Вновь виден рабочий стол.
3. Команда первого опыта дана при открытом окне. Известны ТОЛЬКО демонстрации
   первого и второго опытов. Нужная A отсутствует; исходная цель удерживается,
   активация распространяется по наблюдённым связям состояний. Выбирается X,
   подтверждается переход к рабочему столу, возобновляются A и Enter.
   Объединённая демонстрация X → A → Enter не создаётся.
4. **Уточнение пользователя:** символы 2, 3, 4, 5 уже вводились ранее.
   Стенд воспроизводит независимый прежний ввод `5432` в поле CALC, сохраняя
   подтверждения символов, но НЕ связь с командой трат. Затем показывается
   единственная команда `добавь траты 1700`. Контрольная команда
   `добавь траты 2345` не входит в обучение. Цифры выбираются из временных
   вхождений нового запроса. Неизвестные 6, 8, 9 не встроены в алфавит.

Кнопки 01–04 загружают примеры и начальную среду; нажмите «Передать запрос».
«Проверить 4 теста» выполняет сценарии на изолированных копиях и не меняет
открытый эксперимент. Память разных режимов независима.

## Использование существующей модели

Взяты принципы уже реализованных сигналов: ограниченная активация, утечка,
порог, веса, refractory и конкуренция с отказом при близком максимуме.
Для новых цифр используется принцип снятия торможения после подтверждения.
Запрос действия, физический эффект симулятора и получение квитанции — разные
такты. Пауза останавливает также задержки и тайм-ауты.

`Glaz/recognition_state.py` описывает стадии распознавания объекта, а не состояния
мира. В прежнем desktop-ядре `tekyshiy_ekran()` использует подпись изображения.
Для симулятора сделан независимый аналог подписи: отсортированный набор видимых
идентификаторов, наблюдаемое выделение и фокус. Имена поверхностей, таблица
переходов симулятора, невидимые иконки и координаты не входят в подпись.
Выделенная A отличается от невыделенной; перенос иконки не меняет идентичность.
Содержимое поля не входит в идентичность, иначе каждое число стало бы новым миром.

## Граф и распространение

При обучении квитанции заново проверяются исполнением демонстрации на копии.
Из наблюдений строятся:

- вершины признаков и состояния, соответствующего их совместному набору;
- отдельные контекстные вершины показанных действий и связи `next`;
- вершины наблюдённых переходов между состояниями (включая предварительный
  MOVE/CHECK до изменяющего состояние действия);
- обратные возбуждающие связи «результат → переход → исходное состояние»;
- связи соответствия входного символа подтверждённой клавише, только из опыта.

Если очередное действие недоступно, его наблюдённое предусловие становится
временно удерживаемой целью. Это не перевод команды в команду «закрой окно».
В памяти нет процедуры `if A missing: click X` и нет отдельного поиска BFS/A*.

Каждая волна синхронно использует снимок предыдущей волны:

```
input_i = weighted backward input (competing alternatives for state ensembles)
a_i' = clip(decay * a_i + (1-decay) * input_i, 0, 1)
S' = clip(decay * S + (1-decay) * active_weight / learned_input_weight)
a_goal = drive through learned observes links for the needed feature
candidate_transition = clip(0.25 * S + 0.75 * a_transition - inhibition)
```

`discount` применяется на ребре результата к переходу: длинные цепочки
ослабляются. Свежая и накопленная сенсорная поддержка должны пройти общий порог.
Посторонние признаки не уменьшают долю активных выученных входов. Вершины
недоступных переходов могут участвовать в обратном распространении, но не
исполняются из неподходящего мира. Для выбора перехода одна и та же обратная
динамика распространяется от нулевой и единичной активации. Эти волны дают
нижнюю и верхнюю границы установившегося сигнала. Выбор разрешён, когда нижняя
оценка победителя выше порога и верхних оценок всех доступных конкурентов
с численным запасом `1e-8`. Первое пересечение порога само по себе не разрешает
действие; при неразрешённой конкуренции к лимиту волн выполнение останавливается.
Границы пересчитываются при изменении графа, весов, входа цели или параметров
динамики. Это оценка незавершённого распространения при текущем наблюдении
и торможении, а не статистическая уверенность в правильности восприятия.
Параметр `margin` по-прежнему действует на цели, символы и моторное наведение;
для переходов его заменяет проверка границ. После подтверждения перехода исходное действие
проверяется заново. При необходимости происходит ещё одна волна, а не скрытое
исполнение вычисленного заранее списка будущих действий. Нулевой вес обратной
связи действительно блокирует соответствующий обход.

В обычном показанном фрагменте следующий контекст задаётся связью `next`;
готовность действия накапливается как `a'=clip(decay*a+weight)`, затем порог,
проверка среды и подтверждение. ID — адресация, не числовой порядок действий.
Пределы: 60 волн без решения, 12 переходов обхода, 1800 тактов, 6000 операций.

## Отдельные эффекты и подтверждения

Среда располагается в `environment.mjs`; только здесь известно, что A открывает
окно по Enter и что X закрывает его. Движок получает `observeWorld()` и квитанции.
Кнопки «Рабочий стол / Открытое окно / CALC» задают начальные условия, НЕ создавая
знаний о переходах. Перед эффектом объект проверяется повторно. Устаревший preview
и повторная квитанция не способны повторно выполнить клик.

На ручной доставке мир может уже поменяться, но цель и текущее вхождение ещё
удерживаются. Потеря квитанции не разрешает автоматическое повторное действие.
Подтверждённый иной исход тормозит ошибочное ожидание; исходная цель сохраняется.
Потеря кадра и неподтверждённая отправка не ослабляют причинные связи.

## Новые цифры

Сопоставление клавиш с единственным совпадающим заключительным участком запроса
осталось **заданной общей индуктивной гипотезой**, а не открытием значения слова
«траты». В этой версии одной демонстрации достаточно, но это гипотеза, не
доказательство её единственности. Префикс сопоставляется точно, включая регистр.

Временные вхождения хранят порядок и собственный удерживаемый след. Остаточная
активация, текущий вход, известная моторная связь и торможение предшественником
формируют готовность клавиши. После подтверждения гасится одно вхождение, а не
все одинаковые цифры. В сравнительных опытах явно задан `plasticity:0`.
Встроенного алфавита `0..9` нет: тест без прежнего опыта 5432 отклоняет 2345.

## Граница нейроподобия

Это исследовательский инженерный граф с нейроноподобными накоплением,
затуханием, порогами, торможением и рабочей памятью цели. Это НЕ точная или
доказанная модель человеческого мозга. Наблюдатель, канонизация состояний,
сопоставление примеров, условия допустимости и выбор фазы заданы программно.
Обратные волны — непрерывные уровни активации, а не биофизическая модель спайков.
Видимость из симулятора достоверна; OCR/Glaz и реальные окна ОС не подключены.

Теоретический ориентир накопления, сброса и порога:
Gerstner et al., *Neuronal Dynamics*, §1.3,
https://neuronaldynamics.epfl.ch/online/Ch1.S3.html
Он не служит доказательством биологической точности выбранного планировщика.

## Проверки и хранение

- `npm test`: прежние модульные проверки и `tests/states.test.mjs`.
- `python tests/states_browser.py`: HTTP E2E четырёх сценариев, реальное обучение
  через кнопки, пауза/один такт, ручная квитанция, импорт, IDB reload, четыре режима.
- `KOLOS_INLINE_TEST=1` использует set_content в ограниченном браузере; НЕ
  утверждает проверку реального скачивания или перезагрузки IndexedDB.
- `node tests/states_benchmark.mjs`: изолированный протокол четырёх сценариев и
  перебор новых чисел из наблюдённых цифр, без обучения контрольным запросам.

Отдельная IndexedDB `KolosStateLab`; ошибка хранения видна, JSON доступен.
Версионированный журнал операций воспроизводит среду/веса на копии.

## Самостоятельный опыт v2

Обычный `StateEngine` начинает с `plasticity:1`. В параметрах лаборатории есть
переключатель 0/1; прежние контрольные наборы устанавливают 0. Общие модули
`dynamics.mjs` и `experience.mjs` зеркально соответствуют Python. Участвовавший
шаг оставляет след с затуханием 0.90. При подтверждённом результате изменяется
только причинная связь результата с переходом: `0.05*e*(1-w)` либо `-0.05*e*w`.
Неожиданный результат может добавить новый переход для уже выполненных действий;
команды и их порядок не переписываются. Повторный опыт не создаёт дубликатов.

MOVE/CHECK остаются частями моторного фрагмента и не создают переходов среды.
Пустые фокус/выделение и моторные отметки не определяют состояние. Мысленное
возбуждение не обучает граф. В графе диагностируются сенсорный вход, поддержка
цели и торможение, в журнале — наблюдения и изменения связей.

Файл настоящей памяти ПК `memory.json` v2 хранит сам граф; правила миграции,
записи и обязательная приёмка Windows описаны в `../../kolos_states/README.md`.
Браузерный экспорт остаётся журналом воспроизводимого лабораторного опыта.
История не действует на живой мир; импорт всегда на паузе.


## Acceptance-gate

Четыре сценария выше являются **обязательными для подтверждения работоспособности
алгоритма как набора заявленных возможностей**, а не просто примерами интерфейса.
Полная проверка вынесена отдельно, чтобы её не было обязательно выполнять на
каждом быстром цикле разработки.

Команды:

```
npm run test:acceptance
npm run test:acceptance:browser
```

Формальные критерии и правило релизного подтверждения: `web/ACCEPTANCE.md`.

## Дополнение: 10 базовых возможностей

`goal-network.mjs` добавляет необязательный вход желаемых результатов к тому же
графу опыта. Командный режим 1–4 сохранён. Новые 5–10 используют удерживаемые
вхождения целей, их взаимное торможение, распространение по исходным переходам,
прогноз до действия и временный тормозящий след ошибки. Полный маршрут не хранится.

Кнопки 05–10 показывают эксперименты; «Проверить 10 тестов» не меняет текущую память.
«Задать желаемый результат» — явный конструктор наблюдаемой цели, не естественно-
языковой интерпретатор. Контекстные шаги показанных фрагментов по-прежнему `next`.
План, критерии, причинные проверки, частота и границы: `web/CAPABILITIES.md`.
