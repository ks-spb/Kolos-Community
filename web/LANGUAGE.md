# Опыт 12: языковой опыт возбуждает образ

## Задача и границы

Добавить отсутствующее звено `фраза → внутренний образ I → механизм опыта 11`.
На контрольном запуске пользователь передаёт только текст. Поле, содержимое,
список целей и моторный маршрут извне не передаются. Источник языка никогда
не создаёт S и не выдаёт квитанцию внешней среды.

Это ограниченный ассоциативный графовый преобразователь, **не свободное понимание
русского языка**. Поддерживается новая последовательность известных символов
в изученной формулировке. Новая грамматика, перестановка слов, неизвестное
«не», синоним или пунктуация не угадываются. Поддержка нескольких формулировок
появляется после показа каждой. Новая полная фраза в тесте отличается содержимым,
а не неизвестным синтаксисом. Это ограничение нельзя скрывать словом «понимает».

## План реализации

1. Сохранить режимы и обязательные возможности 1–11.
2. Отделить языковой опыт от моторных демонстраций; учить пары фраза/образ.
3. Строить выученные контекстные цепочки, связи символов с уже известными
   представлениями, семантическую вершину поля/состояния и источники подтверждений.
4. Каждый символ удерживать на входе, пока совместимые контексты накапливают
   активацию. Альтернативы держать параллельно до конца фразы.
5. После полного распознавания выбрать образ по максимальному сигналу,
   порогу и отрыву. Впервые создать образ только после этого выбора.
6. Передать активационный результат общему кодировщику I из опыта 11.
   По умолчанию представить без действий; выполнение — отдельное разрешение.
7. Проверить причинную зависимость от связей и независимость источников I/S.
8. Сверить JS/Python по каждому такту, сохранить память и добавить интерфейсы.

## Обучающие пары

Сначала опыт мира уже содержит переходы X → рабочий стол и CALC → поле, а также
известные символы. Эти переходы не учат языковому значению новых фраз.

Пары языка и образа в стенде:

| Фраза | Подписанный образ |
|---|---|
| я хочу увидеть 1700 в поле | FIELD = 1700 |
| я хочу увидеть 2345 в поле | FIELD = 2345 |
| пусть в поле будет 1700 | FIELD = 1700 |
| пусть в поле будет 2345 | FIELD = 2345 |
| сделай в поле 1700 пожалуйста | FIELD = 1700 |
| сделай в поле 2345 пожалуйста | FIELD = 2345 |

**Контроль:** `я хочу увидеть 1354 в поле`. Ни такая полная фраза, ни моторный
маршрут X → CALC → 1354 не показаны. Цифры уже известны отдельно.

Здесь нет заранее встроенных русских слов, перечня команд, цифровой регулярки,
внешней языковой модели или распознавания «суммы».

## Заданная общая гипотеза обучения — не скрытая магия

При показе пары содержимое поля должно ровно один раз совпасть с непрерывным
участком фразы. Это **программно заданный индуктивный принцип сопоставления**.
Из него строятся буквальные контекстные связи вокруг изменяемого участка,
петля связывания его вхождений и связь с образом поля. Участок может стоять в
начале, середине или конце фразы; цифры не имеют специального статуса.

Два различных содержимых в одинаковом словесном окружении создают два источника
поддержки общего контекста. Повтор той же пары не считается новым независимым
подтверждением. Для образа состояния без переменной части достаточно одного показа.

Таким образом, фразы `zorp AB glip`, `zorp BA glip` могут обучить `zorp BBA glip`
тем же механизмом. Новое сочетание незнакомых слов без пар не будет понято.
Связывание одного непрерывного участка — единственная текущая форма переменной
роли. Несколько полей/значений в одном предложении пока не поддерживаются.

## Вершины, связи и расчёт

`languageMemory` — граф, отдельный от опыта воздействий, но связанный с его
вершинами символов. Он содержит:

- входные знаки `glyph`;
- выученные контекстные вершины и сборки формулировок `assembly`;
- выученные связи `literal` и петлю `bind` для содержимого;
- `ground`: входной знак → известное представление символа;
- `meaning`: представление поля или ранее наблюдённого состояния;
- `readout`: завершённая контекстная цепочка → значение;
- отдельные `witness`/`support` от различных подтверждённых пар.

Текущая фраза создаёт временные вхождения. У каждого связанного символа хранится
его исходная позиция и конкретная связь grounding. Выходной символ берётся из
вершины назначения этой связи, а не из скрытого извлечения числового хвоста.
Переориентация связи действительно меняет выбранное содержимое (контрольный тест).

Каждый такт использует утечку:

`A' = clip(decay * A + (1-decay) * вход)`.

Для обычного перехода: `вход = 0.5 * вес_контекстной_связи + 0.5 * сенсорная_поддержка`.
Для связывания сенсорная поддержка взвешивается выученной `ground`-связью.
Несовпавший с наблюдаемым знаком контекст не получает входа. Контекстные гипотезы
сохраняются параллельно: ранняя похожесть начала не разрешает исполнить фразу.
После завершения фразы:

`вход_значения = min(1, сумма_поддержек) * вес_readout * надёжность_пройденного_пути`.

Порог по умолчанию 0.7; два разных показа дают поддержку 0.4 + 0.4, связь readout
0.9. Накапливается 0.72 с утечкой. Один показ или бесконечное повторение одного
показа дают только 0.36 — недостаточно. Это инженерные параметры, не оценки
из человеческой физиологии. Отрыв 0.04; два разных близких образа дают отказ.
Эквивалентные образы от нескольких формулировок объединяются, но не суммируются
ради искусственного усиления. ID не разрешает равенство.

На границе между модулями победившая семантическая вершина и связанные временные
символы проецируются в существующий кодировщик образа. Он по-прежнему принимает
структурированное представление поля/состояния. Новое отличие: **при контрольном
запуске его получает из обученных языковых связей, а не от выбора пользователя**.
Обычный код нужен для представления входа и сериализации межмодульного сигнала.
Нейроноподобная динамика не означает отсутствия алгоритмических предпосылок.

## Пошаговый контроль

1. Ввести только `я хочу увидеть 1354 в поле`.
2. Все символы распознаются отдельными тактами; до конца нет образа и действий.
3. Значение FIELD и временная последовательность 1,3,5,4 выигрывают по языковым связям.
4. Эти представления возбуждают I; S читается только из среды. Мешающее окно
   остаётся открытым в режиме «представить». Отдельного моторного обучения нет.
5. «Достичь образа» разрешает механизму 11 выбрать X, затем CALC, затем клавиши.
6. Только независимые подтверждения поля/вхождений/конца завершают задачу.
7. Ни языковые связи, ни память мира в контрольном запуске не изменяются.

## Обязательные проверки

- Новое 1354, другие длины, повторы 1001/1111; разные ранее показанные формулировки.
- Содержимое в начале и середине фразы; буквы вместо цифр; известный образ состояния.
- Нулевые literal/ground/readout/support: результат не получается скрытым путём.
- Смена назначения ground меняет смысл символа; связь не декоративна.
- Изменение decay меняет число тактов; перестановка ID не меняет смысл.
- Без языковых пар, с одним примером или дубликатами нет продуктивного обобщения.
- Неизвестные слова, отрицание, неподтверждённый хвост, другое поле, неизвестный
  символ и неполная фраза не игнорируются; нет fallback к старому образу.
- Противоречивые пары конкурируют и останавливаются при близком максимуме.
- Образ от языка не является S и не подтверждает реальное выполнение.
- История/предпросмотр/перезагрузка не выполняют действия и не дообучают сеть.
- Python/JS сравниваются по каждому языковому такту вплоть до образа I/S.
- Реальный HTTP браузер проверяет ввод только текста, обучение через UI,
  сохранение, паузу, шаг, достижение, неизвестную фразу и мобильную ширину.

## Использование

Браузер: «Состояния и цели» → раскрыть **12 · Язык → образ** → загрузить пример.
Он заканчивает чтение, зажигает I и останавливается после восьми тактов образа.
«Понять и представить» — только образ. «Понять и достичь» — явно разрешённое
достижение после однозначного распознавания. Обычные командные режимы сохранены.

Собственные пары: «Обучить связь фразы с образом» → фраза, известное поле и
содержимое → «Запомнить подтверждённую пару». Второй раз — другое содержимое,
то же окружение. В контрольном вводе уже не выбирать поле или число.

Glaz: прежний `run_main.bat`, «Состояния и цели (ПК)» → «Язык → образ».
`/say ФРАЗА` создаёт образ; `/say-run ФРАЗА` также запрашивает выполнение.
`/languagetest` безопасно запускает модельный опыт 12 без реальных кликов.
`/language-teach {"phrase":"...","goal":{...}}` — протокол ручной пары, не парсер
русского языка. Обычная строка, не являющаяся прежней знакомой командой, при
наличии языковых пар проверяется новым языковым режимом без запуска моторики.
Для записи реальных действий остаётся прежняя схема 3/Esc/5/1. Старые базы и
`run_main.bat` не изменяются. Языковая память сохраняется отдельно внутри памяти
нового States-режима, по исходным парам и весам.
