# Текстовое ядро Kolos: границы переноса

Основа: `feature/context-graph`, commit `35aed01eb2bd80ee86bb3119d44ba018a5c7e01d`.
Проверены `main.py`, `graph_viewer.py`, `db.py`. Оригинальные файлы не изменяются.
Это отдельный текстовый адаптер, а не побитовое воспроизведение всех веток desktop-агента.

## Сохранено

- Точка ищется по точному имени; повторный символ переиспользует её.
- Ввод строки идёт по символам Unicode (как итерация строки в Python).
- Сигнал следующей точки равен общему максимуму + 1; остальные сигналы не затухают.
- Каждое событие записи создаёт отдельную направленную связь с новым последовательным ID, включая повторы и петли.
- `online_svyaz`: сохранить кандидатов, для которых существует исходящая связь ID + 1; остальные удалить; новые дописать. Порядок новых кандидатов явно задан по возрастанию ID.
- Выбранный путь хранится отдельно от визуально сгруппированных стрелок. Воспроизведение также записывает новые переходы.
- Отрицательная реакция записывает связь к neg, обнуляет сигнал текущего действия и возвращает состояние к максимальному сигналу.

## Явные решения адаптера и исправления

1. Начальная память детерминирована: poz=1, neg=2, ney=3; старт — ney с сигналом 1. Новые ID точек/связей начинаются с 4. Служебные связи 1–3 не выдумываются и не отображаются. Нулевой максимум/пустая таблица не вызывает ошибку.
2. Равные сигналы разрешаются по минимальному ID. В старом SQL не было ORDER BY, поэтому выбор не был явно определён.
3. После «Новой попытки» фиксируется переход в ney и очищается только краткосрочное состояние. Ни экран, ни Glaz не добавляют неявных токенов.
4. Продолжение выбирается в порядке online-кандидатов; проверяется последовательность ID+1 И совпадение конца предыдущей связи с началом следующей. Требуется завершение в poz/ney, максимум 256 шагов. Пути к neg, заблокированным точкам и оборванные пути отклоняются. Это исправляет небезопасную старую `proshivka`, которая могла склеить несвязанные эпизоды и смешивала ID связи с ID точки.
5. При достижении реакции она записывается как обычное событие состояния и выполнение завершается. Никаких действий ОС, pyautogui, eval, клавиатуры или мыши нет. Краткосрочная память — строка ввода, а не список слов; алгоритм использует признак непустого ввода.
6. Реакции — кнопки, цифры в тексте являются символами. После положительной реакции новый ввод начинает новую краткосрочную попытку, не очищая граф.
7. Визуализация использует собственный SVG, а не PyVis/vis-network: это позволяет точно двигать импульс по тем же кривым без внешних ресурсов. Архитектура сохранена: отдельное ядро, журнал, планировщик, отображение.
8. Сборка: TypeScript + небольшой локальный сборщик вместо Vite. Только TypeScript нужен при сборке; готовый HTML не имеет зависимостей.

## Время и журнал

`preview()` работает на копии состояния. До конца анимации реальная память не меняется. `commit()` атомарно применяет один переход. Пауза замораживает и анимацию, и изменения. «Один шаг» завершает один переход и останавливается.

У перехода отдельно указаны `usedEdgeId` (старая выбранная связь) и `edge.id` (новая запись). Группировка `(from,to)` относится только к SVG. Обратные направления и петли различаются. Для очень длинных подписей на рисунке показаны первые 12 ID, полный список — в сведениях.

Отрицательная реакция визуально проходит по реальной связи к neg; возврат активного состояния к прежнему максимуму не изображается как переход по несуществующей стрелке.

История восстанавливается без повторного обучения. JSON содержит версию алгоритма, команды, очередь, координаты и скорость. Состояния и журнал детерминированно пересчитываются; импортированные графы/HTML не исполняются и не принимаются на доверии. Эксперименты другой версии отвергаются.

## Виртуальные действия

Для проверки гипотез desktop-агента добавлен отдельный тип точки `ACTION`.
Команда пользователя по-прежнему идёт по символам `in`, а демонстрация
кодируется отдельными токенами: `MOVE`, `CHECK object`, `CLICK object`,
`KEY value`. Поэтому символ `1` из запроса и клавиша `1` не смешиваются.

Виртуальный экран не входит в алгоритм выбора пути. Он является средой
исполнения. Перед фиксацией шага `CHECK`/ `CLICK` браузер проверяет
ожидаемый объект: при переносе объекта находит его по имени и переносит
курсор; при отсутствии объекта отменяет preview шага, не меняет граф и не
выполняет click/key. `MOVE` воспроизводит записанные координаты, после чего
`CHECK` исправляет позицию по фактическому состоянию среды.

Обучение повторяет схему desktop Kolos: «Начать обучение» накапливает
демонстрацию во временном буфере, Escape завершает запись, «Сохранить
демонстрацию» переносит действия в граф, а «Правильно» добавляет poz.

## Ограничения

Нет SQLite-импорта, синхронизации между устройствами и настоящего управления
мышью/клавиатурой ОС. Виртуальный экран — безопасный симулятор для проверки
алгоритмических гипотез. Максимум 1000 точек, 5000 событий, 2000 символов за ввод, файл JSON до 5 МБ. Крупные графы просматриваются через поиск, масштаб и режим окружения.

Проверки посимвольного ввода сравнивают каждый шаг с независимым SQLite-эталоном трёх правил из исходника. Они не утверждают эквивалентность неисправленных реакций или полной программы `main.py`.
