# 10 базовых проверок Kolos: план, механизм и критерии

Реализован именно базовый набор 1–10 из обсуждения: четыре ранее обязательных
проверки и шесть следующих. Остальные идеи об AGI не объявляются выполненными.
Результат — проверка ограниченных возможностей инженерной сети, не тест на сознание
и не доказательство создания общего интеллекта.

## Порядок реализации

1. Сохранить исходные четыре сценария и их правила. Не менять Legacy v4,
   предыдущие три браузерных режима и исходный способ запуска Glaz.
2. К существующему графу наблюдённых состояний/переходов добавить временный граф
   желаемых результатов. Вход цели задаётся явно; исполнитель не получает маршрут.
3. Использовать ту же обратную волну возбуждения, веса, утечку и пороги. Выбранный
   переход допускает только действия, ранее наблюдённые в его фрагменте.
4. Добавить удерживаемые вхождения целей и торможение следующей предыдущей.
5. Перед действием записать ожидаемые наблюдаемые признаки. Несовпадение возбуждает
   временную тормозящую вершину данного перехода; исходная цель сохраняется.
6. Проверить положительные случаи и причинные вмешательства: убрать связь,
   выключить возбуждение/торможение, изменить веса/decay, переставить ID.
7. Реализовать одинаковую динамику в JS и Python; сверять по каждому такту.
8. Добавить кнопки тестов/конструктор целей, отчёты, независимые ручные CI-прогоны.

## Матрица обязательных возможностей

| № | Что известно до проверки | Контрольное задание | Критерий |
|---|---|---|---|
| 1 | Показаны A → Enter | Повтор из рабочего стола | Только Enter после выделения открывает окно |
| 2 | Показан клик X | Закрыть открытое окно | Наблюдается рабочий стол |
| 3 | Только отдельные показы 1 и 2 | Команда 1 при скрытой A | По сигналу X → рабочий стол, затем исходные A → Enter; объединённого показа нет |
| 4 | Прежние клавиши 5432; единственный показ трат 1700 | Добавь траты 2345 | Новый порядок клавиш без обучения контрольным числом, ACK каждого вхождения |
| 5 | Отдельные открытия, закрытия, ввод | Сначала состояние открытого окна, затем FIELD = 3521 | Два удерживаемых результата; A → Enter → X → CALC → 3521 получается по графу, не склейкой макросов |
| 6 | Два пути: прямой и через промежуточное состояние | Достичь одного и того же результата | Слабый прямой путь проигрывает сильному обходу; усиление прямого меняет реальный выбор |
| 7 | Знакомое закрытие мешающего окна и открытие поля | Ввести 2345, но после открытия CALC неожиданно появляется окно | Наблюдение меняется, цель сохраняется; X → CALC → ввод без слепого продолжения |
| 8 | Три перехода показаны по отдельности | Из первого состояния достичь четвёртого | Все три перехода составлены на новом запуске без показа полного маршрута |
| 9 | Переходы и алфавит известны; соответствующая команда не вводится | Желаемое наблюдение FIELD = 2345 | Из окна самостоятельно X → CALC → 2345; распознаватель команд не используется |
| 10 | Известны прямой путь, обход и возврат | Прямой переход неожиданно приводит не туда | Прогноз существует до действия; возникает ошибка; ошибочная связь временно тормозится, выбирается известный обход |

Для 1–4 сохранён прежний вход команды. Для 5–10 используется явный вход желаемого
наблюдения. Это разные входы к одной памяти опыта, а не заявление о понимании
фразы «сделай так, чтобы…». Цель не кодируется списком действий и не извлекается
из заранее сохранённого полного решения.

## Что считается нейроноподобным механизмом

- Узлы состояния и наблюдавшегося перехода связаны взвешенными обратными синапсами.
  Синхронная волна использует только предыдущие активности:
  `a' = clip(decay*a + (1-decay)*сумма_взвешенных_входов)`.
- Удерживаемая цель подаёт постоянное возбуждение на соответствующее наблюдаемое
  состояние. Первая неисполненная цель тормозит следующую. Это временные вершины
  и связи, появившиеся из порядка внешнего задания, не новый долговременный «навык».
- Допустимые переходы конкурируют: `A = 0.25*наблюдаемое_предусловие +
  0.75*возбуждение_перехода - errorGain*след_ошибки`. Порог и минимальный отрыв
  обязательны; равные максимумы не разрешаются ID.
- В новом входе цели порог маршрута 0.55, чтобы проверить три независимых перехода.
  Порог 0.65 исходного командного режима не изменён. Остальные стартовые настройки:
  decay 0.5, discount 0.9, порог действия 0.7, refractory 2, errorDecay 0.995.
  Эти коэффициенты инженерные и не оценены из физиологических данных.
- Символы желаемого поля — отдельные вхождения. Они сохраняются до квитанции.
  Предыдущее вхождение тормозит следующий ввод численным вкладом, не скрытым индексом.
- Несовпадение ожидаемых и наблюдаемых признаков возбуждает тормозящий след
  конкретного перехода. Он затухает; постоянные веса не переписываются автоматически.
- Выбранный фрагмент опыта продолжает идти по существующим контекстным связям
  `next`. Новый модуль не скрывает этот факт и не выдаёт их за биофизику нейронов.

Никакой BFS/A*, языковой модели, числового парсера «суммы» или правила
«если A закрыта — нажать X» в новом модуле нет. Обычный код остаётся необходимым
для получения наблюдения, сравнения признаков, синхронного расчёта и отправки
элементарного воздействия в среду. Эти интерфейсы не выбирают маршрут.

Научный ориентир для накопления, утечки и порога: Gerstner et al., *Neuronal
Dynamics*, §1.3, https://neuronaldynamics.epfl.ch/online/Ch1.S3.html .
Это обоснование семейства моделей, а НЕ доказательство, что выбранная сеть
работает в точности как человеческий мозг. Обратная волна здесь использует
непрерывные уровни активности, а не детальную биофизику спайков.

## Проверяем не только правильный ответ

1. Нулевые обратные веса: путь исчезает, скрытого готового решения нет.
2. Нулевое возбуждение цели: не происходит действий.
3. Убрать торможение между целями: возникает конкуренция, второй результат не
   выполняется тайным процедурным индексом.
4. Убрать торможение цифр: возникает неоднозначность, а не сохранённый правильный порядок.
5. Убрать торможение от ошибки: ранее ошибочный маршрут повторяется; тест видит это.
6. Изменить вес маршрута: меняется фактический первый клик.
7. Изменить decay: меняется число волн при сохранении достижимой цели.
8. Перенумеровать/перемешать вершины и связи: результат сохраняется.
9. Новые длины и повторы 1001, 1111, 54321, 700005: по одному ACK на вхождение.
10. Потерянная/повторная квитанция: нет дублированных действий и ложного успеха.
11. История/JSON-повтор: только копия среды, без воздействия на текущий мир.
12. Python и JS: сравнение всех тактов шести новых случаев, включая прогноз и ошибку.

Контрольные эффекты меняет только стенд (intervention). Функции inference не
импортируют файл сценариев и не читают таблицу физических переходов мира.

## Запуск и частота

Быстрая проверка: `cd web && npm test` (unit, включая причинные проверки; без браузера).
Полная алгоритмическая приёмка: `npm run test:acceptance`.
Браузер: `npm run test:acceptance:browser` после установки Playwright/Chromium.
Перебор 2056 комбинаций оставлен отдельным `npm run test:acceptance:exhaustive`.
Python: `python -m kolos_states.cli --acceptance` либо
`python -m kolos_states.capabilities --evidence tests/desktop-output/capabilities`.
Сравнение языковых портов: `python -m unittest discover -s tests/desktop -v`.

В Glaz новая кнопка «10 тестов» запускает только модельные проверки, НЕ действия
на рабочем столе. «Задать цель» позволяет выбрать реальное ранее наблюдаемое
состояние/поле и отправить явные результаты. Разрешение живого управления и F9
остаются обязательными. Браузерная кнопка «Проверить 10 тестов» использует отдельные
копии; кнопки 05–10 загружают стенд для пошагового просмотра.

Полный набор обязателен перед заявлением о поддержке этих возможностей,
изменением логики или релизом. Долгий браузерный прогон и перебор не обязательны
для каждого изменения подписей. Непройденный, пропущенный и пройденный тест —
разные статусы; старый зелёный результат нельзя выдавать за проверку нового commit.

## Границы

- Все примеры — конечные, ранее наблюдавшиеся состояния, точные признаки и известные
  клавиши. Перенос через произвольные новые зрительные признаки не реализован.
- Новые цели задаются структурированно, а не понимаются из естественного языка.
- Тест 7 меняет мир до клавиатурного ввода. Надёжное восстановление после произвольного
  внешнего редактирования текста не заявляется; конфликт содержимого останавливает ввод.
- Тест 10 касается наблюдаемого неожиданного результата и известных обратных путей.
  Отсутствие подтверждения не считается безопасной ошибкой и не запускает повтор.
- Веса долгой памяти в контрольном запуске неизменны; ошибка создаёт кратковременное
  торможение. Автоматическое долговременное переобучение после одной ошибки не добавлено.
- Проверка Windows-адаптера отдельно от способности ядра. Симуляционный PASS не
  означает PASS всех десяти задач в реальных приложениях на компьютере пользователя.
