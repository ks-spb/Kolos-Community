## Что интегрировано

Обычный `run_main.bat` по-прежнему запускает `Glaz/main.py`. Этот файл создаёт
`NeuralStudioApp`, наследующий интеграцию `IntegratedScreenCaptureApp` и исходный
`ScreenCaptureApp` без замены `Glaz/app.py`. Классический интерфейс доступен через
`GLAZ_UI=classic`. В панели терминала появился выбор `Legacy v4` / `Состояния и цели (ПК)`.
Legacy запускает прежний корневой `main.py`. States запускает
`python -m kolos_states.cli` тем же интерпретатором. Node.js нужен только для
сравнительных тестов при разработке, не при работе на ПК.

Новый `core.py` — Python-перенос `web/states/core.mjs` (основание ef97a1cf).
Сохранены веса, decay, пороги, refractory, обратная волна цели, контекстные связи
`next` и снятие торможения входного вхождения после подтверждения.
На 4 сценариях сравниваются по тактам кандидаты, активации, цель, контекст,
входные вхождения и выбранные переходы с независимым исходным JavaScript-ядром.
Это не заявление о биофизической модели мозга или об отсутствии программных
правил сопоставления демонстрации. Сохранена прежняя инженерная модель.

## План интеграции и разделение ответственности

1. Выделить переносимое Python-ядро без импорта мыши/Glaz/симулятора.
2. Оставить прежний запуск и терминал; добавить явный переключатель движка.
3. Добавить отдельный канал свежих наблюдений Glaz, используя существующие
   пики, подписи лупы и базу узнаваемых объектов. Не использовать старый
   geometry-only cache как доказательство актуального экрана.
4. Отдельный исполнитель проверяет объект/фокус, выполняет одну операцию и
   ждёт независимое наблюдение результата. Возврат функции ввода не является ACK.
5. Перенести запись демонстрации и прежний ввод клавиш, отдельную память,
   остановку, паузу, просмотр сигналов и проверку четырёх возможностей.
6. Сравнить математическое ядро с JS; проверить границы отказов; отдельно
   проверять настоящий запуск Glaz на Windows и доступность наблюдения поля.

## Установка и запуск

- Обновить файлы проекта из ветки `feature/browser-graph-lab`.
- Один раз выполнить `install_states.bat`. Зависимости устанавливаются командой
  `py -3 -m pip install -r requirements-states.txt` в тот Python, который использует
  неизменённый `run_main.bat`. Администраторские права не требуются и не запрашиваются.
- Запустить привычный `run_main.bat`.
- При запуске в панели Kolos выбран движок `Состояния и цели (ПК)`.
  Для явного старта Legacy допускается переменная `KOLOS_ENGINE=legacy`.
- Выбрать монитор и включить захват Glaz. Желательно держать Glaz на другом мониторе:
  его собственное окно исключается из наблюдений и закрывает находящийся под ним мир.
- Сначала нажать `4 теста`: это безопасные модельные проверки без управления ОС.
- Галочка `Разрешить управление ПК` включена при запуске States.
  Разрешение действует только на текущий сеанс; при смене движка или STOP
  сбрасывается. Повторное включение галочки требует подтверждения диалога.
- F9 или кнопка STOP — аварийная остановка. Corner failsafe PyAutoGUI не отключается.

## Первая проверка на реальном экране

Кнопка `Тестовое окно` запускает отдельное настоящее Win32-окно со стандартными
кнопками и EDIT-полем. Оно предназначено для контролируемых первых проб и не имеет
доступа к файлам/платежам. Оно НЕ передаёт движку свои правила и внутреннее состояние:
Glaz наблюдает изображение, UI Automation читает выделение/поле.

Сначала наведите мышь на нужные элементы и дождитесь их ID в Glaz: новый bridge
узнаёт только зарегистрированные объекты, не присваивает им значения A/X/CALC.

1. На тестовом рабочем столе введите `открой окно`. Неизвестный запрос останется
   подготовлен для обучения. `3` / Запись → вернуться в тестовое окно за 2 с →
   клик A → дождаться сообщения «Клик записан» → Enter → дождаться
   наблюдения → Escape → `5` → `1`.
2. При открытом окне: `закрой окно`, аналогично показать клик X, сохранить и
   подтвердить. Повторить команды из соответствующих исходных состояний.
3. При открытом окне передать `открой окно`. Исходная цель должна удерживаться,
   волна выбрать изученный возврат через X, после ACK возобновить A и Enter.
4. В поле CALC сначала показать независимые клавиши `5432`; сохранить запись
   через `5` → `/expose` вместо `1`. Затем показать `добавь траты 1700` с кликом
   CALC и клавишами `1700`; выполнить новый запрос `добавь траты 2345`.

Демонстрации в этой версии записываются медленно: следующее действие — после
сообщения о записи предыдущего. Клик записывается по подтверждённому ID Glaz и
событию мыши, даже если выделение иконки не видно. После него терминал пишет
«Клик зарегистрирован»; наблюдение результата продолжается до следующего действия
или завершения записи. Результат принимается по двум свежим согласованным кадрам;
при завершении записи наблюдатель ждёт до шести секунд. Если несколько клавиш
попали в поле между наблюдениями, запись отклоняется, а не создаёт выдуманные
промежуточные кадры.
Если при наведении Glaz подтвердил другой ID для тех же точных границ объекта,
это записывается как фактически показанная последовательность MOVE → CHECK:
например, образ №50 до наведения и №63 после него. Образы не объединяются,
MOVE/CHECK не обучают переходы среды. Пересечения с другими границами отклоняются.
Backspace, Ctrl/Alt-комбинации, перетаскивание, правый клик и внутренние блоки ввода
с последующими действиями пока не поддерживаются. Enter поддержан как действие
над наблюдаемой выделенной иконкой или последним подтверждённым кликом по ней,
не как произвольное подтверждение формы.

Цифры 0–9 поддерживаются на основном ряду и NumPad с включённым Num Lock.
Reset отменяет незавершённую демонстрацию и очищает удержание курсора/распознавание,
чтобы следующая запись снова определяла объект при наведении и центрировала курсор.

## Подтверждение в настоящей среде

`states_bridge.py` повторно детектирует объекты из свежего кадра. Ответ содержит
сеанс, ID запроса скана, время захвата, монитор, абсолютные координаты и bbox.
Устаревшие ответы и разные сеансы не принимаются; одинаковые неоднозначные ID
не разрешают клик. Пока движок исполняет, автоцентрирование Glaz не борется с мышью.

`DesktopAdapter` повторно проверяет объект перед действием. После отправки
нужны два последовательных свежих наблюдения согласованного результата:

- MOVE: наблюдаемая позиция курсора;
- CHECK: нужная иконка действительно под курсором;
- CLICK: два свежих согласованных наблюдения результата; у изученного клика
  без изменения разрешён только моторный шаг, без причинной связи результата;
- ENTER: наблюдаемое изменение; несовпадение с ожиданием обрабатывает ядро;
- KEY: то же читаемое поле и точное изменение `before.output + symbol`.

Для Enter Glaz также сравнивает два изображения выбранного монитора: кадр после
клика и свежие кадры после Enter. Большая смена изображения свидетельствует об
изменении, но сама по себе не доказывает конкретное окно или появление иконки.

Если до отправки действия цель временно исчезла из наблюдения, Kolos проверяет
её повторное появление на каждом такте поиска. Свежая однозначная цель позволяет
продолжить исходный шаг, даже если другие иконки рабочего стола изменились.
Несколько распознанных экземпляров одного ID считаются взаимозаменяемыми:
для обычной команды выбирается ближайший к текущему курсору центр значка.
При равном расстоянии выбирается верхний, затем левый экземпляр; порядок
обнаружения не влияет на выбор. Записанный MOVE перед CHECK/CLICK использует
свежие координаты выбранной иконки уже при первом наведении. Перед кликом
объект снова проверяется под курсором; отсутствие цели не разрешает клик.
Сохранённые команды переобучать не требуется. Для команд, связанных с составным
образом, выбор по значку и подписи остаётся обязательным.
Уже отправленное действие не повторяется.

Полное наблюдение принимается в течение трёх секунд после захвата. Если ответ
устарел при распознавании или передаче, запрашивается новый скан в пределах
исходного восьмисекундного ожидания; движение и клик при этом не повторяются.
Долгий расчёт можно подтвердить более новым реальным снимком того же монитора,
только если размер, режим и все пиксели двух снимков совпадают и захват включён.
Изменившийся экран требует нового распознавания. Журнал узнавания объекта
обновляется после передачи полного наблюдения и сам по себе его не заменяет.

Glaz выбирает экземпляр среди свежих распознанных объектов под курсором.
Нераспознанный контур подсветки и копии того же ID в других местах не мешают
этому выбору. Среди вложенных распознанных рамок выбирается единственная внутренняя.
Равные рамки и частичные пересечения распознанных целей остаются неоднозначными.
В выученной связке CLICK → Enter выбор фиксируется успешной отправкой клика.
Колос сразу переходит к Enter без подтверждающих кадров после клика и без
повторного поиска объекта. Подсветка, раскрытая подпись или новый Glaz-ID не
отменяют выбор. Перед Enter свежий кадр служит исходным изображением для проверки
результата; смена окна, фокуса или данных UIA не отменяет сохранённую связку.
Явный стоп, отзыв разрешения на ввод, сброс, новая попытка или другое моторное
действие снимают этот след; пауза приостанавливает отправку. Результат Enter
по-прежнему должен быть наблюдён; ввод автоматически не повторяется.

Windows UI Automation дополняет зрение наблюдаемым выделением и текстом
ValuePattern/TextPattern. Содержимое поля и координаты не определяют идентичность
состояния. Сам запрос не парсится на «сумму».

Для чтения поля нужна зависимость `uiautomation` в том же Python, которым
`run_main.bat` запускает Glaz. `install_states.bat` устанавливает её вместе с
остальными зависимостями; после установки перезапустите Glaz. Запись и выполнение
проверяют наличие библиотеки до начала действий. При остановке ввода сообщение
также показывает причину из UI Automation, а не только отсутствие фокуса.
В команде `Впиши 12345` покажите клавиши `12345`; если команда содержит
`1 2 3 4 5`, покажите и пробелы. После двух демонстраций с одинаковой формулировкой
и исходным состоянием `Впиши 12345` / `Впиши 6789` можно выполнить `Впиши 4532`
из известных символов без отдельного обучения этой последовательности.
Наведения MOVE → CHECK на один подтверждённый объект сравниваются по объекту,
а не по пикселям курсора. Две записи одинакового открытия Блокнота с небольшим
отличием наведения расширяют известный набор клавиш. Уже сохранённые дубликаты
также сравниваются по реальным шагам графа; переобучение после обновления не нужно.
Разные объекты, поля, наблюдаемые состояния или условия подтверждения остаются
разными вариантами команды. «Язык → образ» связывает фразы с желаемым состоянием
или содержимым поля; для нового порядка уже показанных клавиш этот режим не нужен.

**Не каждый элемент приложения предоставляет доступный текст или выделение.**
Встроенный Windows Calculator часто предоставляет результат через особый read-only
элемент, а не редактируемое поле; такой элемент этой универсальной версией не
объявляется подтверждённым вводом. Первую проверку клавиш делайте в доступном EDIT-
поле тестового окна/приложения. Для нечитаемых контролов нужен отдельный наблюдатель;
автоматический фиктивный ACK и OCR здесь не добавлялись.

При неподтверждённом исходе действие НЕ повторяется, источник НЕ гаснет. После
F9/потери наблюдений надо осмотреть экран и явно отменить попытку `/reset`.
Изменение уже отправленного внешнего действия паузой отменить невозможно.

## Память и возврат к старой версии

Нативная память: `~/.kolos/states-memory/<идентификатор-папки-проекта>/`.
IPC: `~/.kolos/states-ipc/<случайный-сеанс>/`. Обычный пользовательский доступ;
это граница процессов одной учётной записи, не защита от вредоносного ПО на ПК.
`db_v4.db` и формат объектов Glaz не меняются. Вторая копия процесса не получает
ту же память одновременно. Запуск после сбоя не возобновляет прежние действия.

Браузерные демонстрации A/X/CALC не импортируются как настоящие координаты/ID Glaz.
Реальную среду надо показать заново. Кнопка `Сигналы` показывает A/T/R и удерживаемые
вхождения Python-ядра; это таблица текущего графа, не браузерная анимация.

## Проверки

`python -m unittest discover -s tests/desktop -v` — модель и границы (Node только
для теста сравнения с JS). `python -m kolos_states.cli --selftest` — 4 обязательных
возможности без GUI и без Node.

Windows smoke запускается отдельно при `KOLOS_WINDOWS_SMOKE=1` после установки
зависимостей: настоящий Glaz поднимает native-child с запрещёнными действиями;
отдельное Win32-поле проверяет чтение UIA после реальной клавиши. Эти проверки не
равны прохождению всех четырёх опытов на произвольных приложениях пользователя.

## Дополнение: цели и 10 проверок

Новый `goal_network.py` — перенос необязательного входа целей к существующему
ядру, а не замена прежних четырёх тестов. В Glaz добавлены «10 тестов» (изолированные
модельные проверки) и «Задать цель» (выбор наблюдаемого состояния/поля).

`/goals [{"kind":"field","focus":"реальный ранее наблюдаемый ID поля","value":"2345"}]`
задаёт желаемое наблюдение; не готовый список действий. Поля можно выбрать в диалоге,
не вводя их технические ID вручную. `/acceptance` либо
`python -m kolos_states.cli --acceptance` запускает все десять без управления ОС.

Для нового входа целей адаптер может вернуть устойчивый наблюдаемый, но отличающийся
от прогноза исход. Он не маскируется как успех цели: возбуждается тормозящий след
перехода, цель удерживается, допускаются только другие изученные переходы.
Неопределённый исход/нет квитанции по-прежнему останавливает выполнение без повтора.
Та же динамика применяется к командному режиму.

Подробный план и ограничения: `web/CAPABILITIES.md`. Все новые уравнения и
кандидаты сверяются по тактам с JS. Это не подтверждает прохождение всех десяти
опытов в приложениях пользователя; нужны отдельные надёжные наблюдения Glaz/UIA.

## Опыт 11: образ и восприятие

«Задать цель» → «Представить без действий» запускает только накопление I/S и
обратную волну, без мыши и клавиатуры. После 8 тактов — пауза. «Образ I / S»
показывает общие вершины содержимого с двумя независимыми входами. «Достичь
образа» использует прежнее разрешение управления, свежий Glaz/UIA и F9.
`/image-rest` снимает внутреннюю поддержку; `/imagerytest` проверяет опыт на модели.
Python/JS сравниваются по каждому такту; план и границы: `web/IMAGERY.md`.

## Языковой опыт → образ (опыт 12)

Добавлены `language.py`, потактовое сравнение с JS и диалог Glaz **«Язык → образ»**.
Пары `фраза / известный образ` сохраняются отдельно от моторных показов. Два разных
содержимых одной формулировки поддерживают её переменную роль. Новый текст сам
активирует поле и содержимое через выученные связи, после чего работает опыт 11.

`/say ФРАЗА` — представить без действий; `/say-run ФРАЗА` — затем достичь при
наличии отдельного разрешения ПК. При паузе право автоматического достижения
снимается. `/languagetest` — только модель, без мыши. Прежний run_main не изменён.
Вторая часть диалога обучает пары, первая принимает только текст без выбора цели.

Поддерживаются изученные формулировки с новыми комбинациями известных символов,
не произвольная грамматика. Синонимы надо показать; неизвестное отрицание не
игнорируется. Общее правило сопоставления непрерывного участка задано программно.
Подробности и приёмка: `web/LANGUAGE.md`. Реальные ПК-окна требуют независимого
наблюдения Glaz/UIA; зелёный модельный тест не подтверждает все приложения Windows.

## Нейроны: живой диагностический граф

Кнопка **«Нейроны · живой граф»** открывает локальный браузерный просмотр текущего
States-ядра Glaz. Это только чтение, без управления мышью/клавиатурой: пауза и F9
ядра остаются в Glaz. Видны вершины, I/S, активации, кандидаты, веса и вклад связей;
история не повторяет действия. Нужны файлы `web/neurons/` и `web/states/` из той же
версии проекта. На одном мониторе браузер может закрывать рабочую область —
используйте второй монитор либо просмотр записанного опыта. Подробности и
проверяемые ограничения: `web/NEURONS.md`.

## Все 12 возможностей в одной памяти

`python -m kolos_states.shared_experiment` / `/sharedtest` выполняют двенадцать
на одном учебном экземпляре Python, не создавая отдельную базу перед каждым тестом.
В Glaz добавлена «Общая учебная база · 12 опытов»: открывается безопасная визуальная
проверка общей виртуальной среды. Она не заменяет вашу реальную память ПК.
План и ограничения: `web/SHARED.md`.

В основном ядре альтернативные входы состояния теперь конкурируют вместо
безусловного усреднения со всеми соседями. Общий `stateCompetition=1` одинаков для
всех задач; `0` воспроизводит прежний расчёт для сравнительного контроля. Это
устраняет проверенную помеху дополнительных знаний без per-test настроек или
удаления связей. Точное математическое соответствие Python/JS проверяется по
шагам общего набора. Legacy main.py не изменён.

## Восстановление и самостоятельное обучение, память v2

При заблокированном действии удерживается нужный наблюдаемый признак — видимость,
выделение или фокус. Сигнал идёт по имеющимся `observes` и обратным связям.
Сенсорная поддержка — доля активных взвешенных входов выученного ансамбля;
посторонние значки её не уменьшают. Поддержка накапливается с `decay`.
Переход конкурирует по `0.25*S + 0.75*A_цели − торможение`, общему порогу и отрыву.
Свежие моторные проверки сохраняются. Только внешнее наблюдение нужного признака
освобождает исходный шаг. Новых типов вершин, таблиц обходов и правил O1 → O2 нет.

`clicked:*` исключён из признаков среды. Краткий моторный след подтверждённого
клика разрешает последующий Enter, даже если выделение изменило распознавание
иконки. Смена окна, фокуса, текста, большая смена изображения или выделение
другого объекта снимают этот след. Он не разрешает клик по отсутствующему объекту.
Совпадения того же зрительного ID в других местах и изменения списка распознанных
значков не отменяют уже подтверждённый клик по конкретному экземпляру. Проверка
Enter использует этот моторный след; новый CLICK/CHECK требует проверки под курсором.
Само исчезновение распознавания без новых признаков или изменения изображения
не считается эффектом. Одного пропущенного обнаружения недостаточно для отказа:
исполнитель повторно наблюдает экран перед отправкой, сохраняя проверки объекта.

После обхода курсор может остаться у другого объекта. Если нужный зрительный ID
наблюдается в нескольких местах, заблокированный CHECK возбуждает предшествующий
изученный MOVE через существующую связь `next`; CLICK использует цепочку
MOVE → CHECK → CLICK. Выбор учитывает сенсорную поддержку исходного ансамбля,
веса, затухание, общий порог, отрыв и рефрактерность. Наведение повторяет показанные
координаты, если подходящий значок пока не наблюдается. При видимой цели MOVE
использует её свежие координаты. Затем CHECK должен подтвердить экземпляр под
курсором. Само движение не снимает цель и не разрешает клик. При неоднозначности
уже в показанной точке движение не повторяется. Эти правила общие для команд
и сети целей Python/JS; версия памяти и сохранённые обучения не меняются.

Пластичность по умолчанию включена. `/plasticity off` отключает изменение весов
и добавление самостоятельного опыта, `/plasticity on` включает. В ядрах это общий
`config.plasticity` (0/1). След участия шага затухает с 0.90; при подтверждении
изменяется только связь результата с участвовавшим переходом:
`Δw=0.05*e*(1-w)` при совпадении, `Δw=-0.05*e*w` при другом результате.
Вес ограничен [0,1]. Ошибочное ожидание получает временное торможение с затуханием
0.995, фактический переход запоминается существующими типами графа с весом 0.9.
Текстовые команды и порядок их действий это правило не переписывает.
Повторные квитанции, отсутствие кадров и мысленные образы не обучают сеть.

`memory.json` v2 хранит граф и веса напрямую, включая самостоятельный опыт.
При загрузке проверяются связи, веса и моторные фрагменты; возбуждение, следы,
торможение и незавершённые действия не восстанавливаются. Старая v1 при первом
запуске сохраняется рядом как `memory-v1-<время>.json`, затем начинается чистая
память. Числовые ID и недоказанный эффект прежнего O2 не переносятся.
`audit` содержит принятые наблюдения, ID изменённых связей, старые/новые веса,
след участия и ID добавленного перехода. Диагностика графа показывает S, поддержку
цели, торможение и итог кандидата по текущим сигналам.

Повторная приёмка Windows после обновления:

1. Перезапустить Glaz/States и заново показать O1: MOVE/CHECK иконки, клик,
   после сообщения о регистрации — Enter; дождаться наблюдаемого результата.
2. Показать O2 на открытом окне: клик крестика, дождаться рабочего стола с нужной
   иконкой и сообщения «Результат наблюдён», затем закончить и подтвердить запись.
3. Открыть окно, закрывающее иконку, передать O1. В журнале должны появиться
   обратная волна, выбор изученного перехода, подтверждение появления иконки
   и продолжение O1. Для просмотра живого графа удобен второй монитор.
4. Перезапустить States и повторить: приобретённые связи должны сохраниться.

`tests/desktop/test_neural_learning.py` проверяет настоящий программный тракт
Recorder → ядро → Terminal → DesktopAdapter на независимой модели экрана,
задержанное закрытие, отсутствие ложной причинности, пропуск кадра, торможение,
обучение и сохранение. Потактовое сравнение с JS включает активности, следы,
торможение, веса и новые связи. Прежние 12 опытов используют явно отключённую
пластичность для сравнительной проверки. Эти тесты не заменяют пункты Windows.
