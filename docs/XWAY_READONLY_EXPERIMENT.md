# Самостоятельный поиск и чтение XWAY с проверкой памяти

11 ноября 2026 года. **Два успешных исполнения на одном другом товаре**, без
вмешательства модели между шагами. Контроли с разорванной связью и пустой памятью
задачу не выполнили. Рекламные настройки не изменялись.

## Результат

Учебный товар: `11016-70х12`, WB ID `1391386148`, наблюдаемый бюджет **50 ₽**.
Проверочный товар: `DEMO-A` (идентификаторы заменены в публичной сводке), бюджет **30 ₽**.
Колос записал текущие артикул, WB ID и бюджет в настоящий локальный JSON-отчёт.
Дополнительное независимое чтение через XWAY MCP подтвердило бюджет 30 ₽ и
включённый XWAY AI; этот MCP не участвовал в исполнении.

Контрольная остановка не считается успешным исполнением задания. Во всех четырёх
запусках память во время исполнения оставалась неизменной. PID: 30104, 37240,
33252, 31404. Подпись обученной памяти в обоих успешных процессах:
`e5be95a23166a288b56d3d6904d7eb3246be9fbe765151f14013fd7d4b1266dd`.

Отключалась именно связь `e13`: `n5 → n12` между чтением задания и вводом
артикула. Название команды и первое чтение оставались рабочими. Тот же
исполнитель после восстановления памяти снова выполнил задачу. Это свидетельство
зависимости выученной последовательности от графа, а не только проверки имени команды.

## Что выбирает ядро и что задано кодом

Внутри эпизодов ядро `StateEngine` выбирает девять операций по сохранённым рёбрам:

1. Прочитать артикул из текущего задания.
2. Ввести прочитанное значение в фильтр артикула продавца.
3. Применить фильтр.
4. Прочитать артикул найденного товара → записать в локальный отчёт.
5. Прочитать его WB ID → записать в локальный отчёт.
6. Прочитать его бюджет → записать в локальный отчёт.

Поиск — прежний трёхшаговый навык из памяти опыта 29 октября, без нового показа
поиска. Для чтения записан **новый шестишаговый показ на живом учебном товаре**:
роли прежнего чтения были привязаны к конкретному товару. Новый показ использует
область `selected product`, а наблюдатель до чтения сверяет обе части идентичности
товара с текущим заданием. На проверочном товаре обучения не было.

Внешний код задаёт два этапа задания **поиск → чтение**, открывает каталог,
ожидает его готовности и открывает редактор фильтра. После применения фильтра
XWAY удаляет редактор; адаптер повторно открывает его для проверки фактического
пустого значения. Эти открытия — служебные действия адаптера, а не выученные
шаги. Они отдельно отмечены как `bootstrap`/`adapter` в журнале. Выбор нового
товара передаётся обычными полями задания; сумма бюджета в задании отсутствует.

Следовательно, это самостоятельное исполнение двух известных навыков в
подготовленном DOM-адаптере. Произвольная постановка цели, зрительное обнаружение
интерфейса и самостоятельное создание нового адаптера здесь не проверялись.

## Исполнитель и граница записи

- `kolos_states/xway_readonly/protocol.py`: роли, точная идентичность и закрытый
  список разрешённых операций. В рекламные поля нет операции записи.
- `kolos_states/xway_readonly/worker.py`: отдельный процесс существующего ядра,
  подтверждение двумя свежими наблюдениями, работа с локальным отчётом, журнал.
  Сетевые соединения из этого процесса запрещены.
- `tests/desktop/xway_executor.mjs`: механический исполнитель через штатный
  браузерный API. У него нет модели, запасной последовательности или доступа
  к рекламному API. Он принимает только чтение, локальную запись, ввод точного
  артикула задания и применение именно его поискового фильтра.

Каждый самостоятельный запуск выполнялся одним вызовом заранее записанного
исполнителя; между действиями Codex не выбирал элементы, не вводил значения
и не исправлял маршрут. Внутри цикла исполнения **0 LLM-вызовов**. Разработка,
учебный показ и проверка результата выполнены Codex и отделены от этого цикла.
Сам журнал не является независимым внешним аттестатом отсутствия вмешательства:
он проверяется вместе с кодом, кадрами и причинными контролями.

Менялся только поисковый фильтр кабинета и файлы локального отчёта. Ни бюджет,
ни переключатель XWAY AI не изменились между исходным и конечным DOM-наблюдением.
Доступ к другим товарам ограничен текущей видимой страницей каталога: автоматическая
пагинация не реализована. Вход в кабинет уже был выполнен в браузерной сессии.

## Подготовительные неудачи

До итоговой серии были два неуспешных запуска исполнителя:
`xway-readonly-trained-20261111A` остановился при загрузке каталога до операций
ядра; `...B` остановился после трёх операций, когда применение фильтра временно
убрало таблицу. Их `result.json`, журналы и кадры сохранены; успех им не присвоен.
Исправлялось ожидание DOM в исполнителе, не обученная память и не ядро.
Также при подготовке обнаружены недоступность запуска дочернего процесса
из браузерной среды и скрытый дубликат закреплённого заголовка: используется
файловый IPC с отдельно запущенным ядром и проверка видимости заголовка.

Все четыре итоговых запуска после этих исправлений используют одинаковые
исходники. Один проверочный товар и два успешных повтора не дают оценки
надёжности на всём ассортименте и не доказывают преимущество перед скриптом.

## Проверки и воспроизведение

Пройдены **60 Python-тестов**: новые ограничения, прежний браузерный мост,
read-only наблюдатель, обучение эпизодам и проверки границ. Пройдены **3 JS-теста**
запрета рекламных записей и подмены артикула. Стандартный Python 3.14 `tempfile`
в ограниченном Windows-процессе создавал недоступную ему папку с mode 0700;
в тестовом запуске только временные папки под проверенным локальным
`tests/desktop-output/xway-unit-temp` создавались с mode 0755. Производственный
код и проверки не подменялись.

```powershell
py -3 -X utf8 -B -m unittest tests.desktop.test_xway_readonly
node tests/desktop/xway_executor.test.mjs
py -3 -X utf8 -B -m tests.desktop.validate_xway_readonly
py -3 -X utf8 -B -m tests.desktop.xway_recording
py -3 -X utf8 -B -m tests.desktop.xway_recording --webm
```

Валидатор сверяет цепочки журналов, совпадение каждой команды исполнителя с
ответом ядра, все подтверждения, 64 исходных PNG, неизменность исходников и
памяти, разные процессы, независимое чтение MCP и отсутствие обучения в прогоне.
MP4 проверены чтением декодером и совпадением количества кадров. `git diff --check`
не обнаружил ошибок пробелов.

Для нового живого запуска сначала стартует отдельный worker:

```powershell
py -3 -X utf8 -u -B -m kolos_states.xway_readonly.worker .\tests\desktop-output\NEW_RUN --files
```

В поддерживаемой браузерной среде импортируется `tests/desktop/xway_executor.mjs`,
создаётся `XwayExecutor(tab, {name, task: {sku, wb_id}, memory, mode})`, затем
одним вызовом выполняется `await executor.run()`. `name` совпадает с папкой worker;
`memory` указывает на `xway-readonly-teach-20261111D/trained-memory/memory.json`.
Варианты `mode`: `trained`, `cut`, `empty`. Нельзя использовать эту команду для
изменения рекламы: соответствующих примитивов у исполнителя нет.

Упрощение: сохранены существующие learner и граф без изменений. Выделены граница
действий, процесс ядра, браузерный мотор и постобработка записи. Зависимости не
устанавливались, git-коммитов и внешних записей не выполнялось.
