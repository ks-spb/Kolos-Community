### Что действительно помогло

1. **Пластичность и сохранение графа**: отключение пластичности возвращает
   200/200 повторений ошибки. Накопленная информация переживает новый процесс.
2. **Проверка завершённости конкуренции**: на одной и той же выученной памяти
   замена прежнего правила уменьшает повторения с 200/200 до 0/200. Раннее
   решение мешало использовать уже полезное обучение; это исправлено.
3. **Композиция ранее показанных переходов** сохраняет перенос и старые навыки
   в проверенной семье миров. Её использует и контрольный планировщик.
4. **Преимущество над Dijkstra не обнаружено**: успешность и скорость обучения
   совпали, вычислительно планировщик быстрее. Новое правило делает динамику
   работоспособной в этом сценарии, но не доказывает её уникальность.

Ограничение: 20 рандомизаций одной топологии. Их одинаковые результаты и
вырожденные интервалы bootstrap в сводке описывают этот набор, а не гарантируют
надёжность на новых типах приложений. Реальное зрение, новые типы действий,
большие графы и сравнение с Hermes/Grok Bot здесь не испытывались.

## Что проверяем

В [первом эксперименте](TRANSFER_EXPERIMENT.md) полезное обучение сохранялось
в графе, но штатный исполнитель продолжал ошибаться после перезапуска.
На той же памяти Dijkstra избегал ошибки. Короткий путь пересекал порог до
прихода сигнала длинного обхода. После стабилизации обход побеждал, однако
разница была меньше прежнего обязательного отрыва `0.04`.

Исправление должно устранять повторение ошибки за счёт выбора по выученному
графу. Успешное завершение после ошибочного действия отдельно от предотвращения
ошибки. Сравнение проводится с обычным планировщиком на той же памяти.

## Изменение алгоритма

Общий модуль `kolos_states/route_selection.py` и его эквивалент
`web/states/route-selection.mjs` используются при достижении цели и при
восстановлении прерванной команды.

Обратное распространение с неотрицательными весами монотонно на `[0, 1]`.
Поэтому две последовательности, начинающиеся с нулей и единиц, ограничивают
установившуюся активацию снизу и сверху. Оба расчёта используют прежний
`backward_wave`, те же веса, затухание, конкуренцию и возбуждение от цели.

Переход выбирается, когда:

1. Его нижняя оценка достигла действующего порога маршрута.
2. Эта оценка больше верхней оценки каждого другого доступного перехода
   с численным запасом `1e-8` — десять единиц существующего округления активаций.

Это не фиксированная задержка на подобранное число тактов. Дополнительные волны
нужны только пока не доказано преимущество. Если за прежний лимит волн решение
не подтверждено, движок останавливается без действия; ID не разрешает равенство.
При изменении графа, весов, входа цели или параметров динамики границы сбрасываются.
После подтверждения фрагмента начинается новый выбор. Границы временные и не
сохраняются в долговременную память.

Фиксированный отрыв `margin=0.04` для переходов заменён проверкой границ.
Параметр продолжает действовать для конкуренции целей, символов и моторного
наведения. Пластичность, Store, квитанции, моторные проверки и граф опыта
не менялись. Все три автономные HTML-сборки включают новый модуль.

Гарантия относится к незавершённому распространению в текущем графе при текущих
сенсорных и тормозных сигналах. Это не статистическая оценка качества весов
или правильности восприятия.

## Зафиксированный протокол

- Разработка и регрессионные тесты: мир `0`; прежний снимок мира `1000`
  использован для диагностики уже известной ошибки.
- Новая отложенная выборка: **2000–2019**, без пересечения с прежней `1000–1019`.
  Код и протокол v3 зафиксированы перед запуском; веса и параметры по результатам
  новой выборки не подбирались.
- Это одна семья топологий с новыми ID, геометрией, порядком демонстраций и
  значениями полей. Новые топологии и приложения не проверяются.
- Семь отдельных переходов и экспозиция алфавита. Полный тестовый маршрут не
  показывается. Пять задач переноса на мир, отвлечение и смещение объектов;
  отдельные проверки дополнительных знаний и отключения связей к цели.
- После изменения эффекта быстрого пути: пять попыток обучения, затем сохранение
  штатным Store и десять проверок в новом процессе. Каждая проверка загружает
  один и тот же снимок, обучение в проверках выключено.
- Для Колоса и Dijkstra есть ветви с пластичностью и без неё. Также каждый
  исполнитель получает граф, обученный другим исполнителем.
- Дополнительный контроль `early`: прежнее первое пересечение порога с отрывом
  `0.04`, на том же графе, обученном исправленным Колосом. Отдельный новый процесс,
  десять попыток, обучение выключено. Меняется только правило выбора.
- Успех проверяет среда: нужное поле, точное значение, отсутствие ввода в
  неверный фокус. Ошибочный быстрый путь считается независимо от итогового успеха.
- Полный прогон: **2400 попыток, 140 новых процессов, 80 снимков памяти**.
  Единица повторения для сравнений — мир, а не каждая из его десяти загрузок.

## Воспроизведение и проверка

Из корня проекта, с новым путём вывода для каждого запуска:

```powershell
python -B -m kolos_states.transfer --seed-start 2000 --worlds 20 --output tests/desktop-output/transfer-selection-v2
python -B -m tests.desktop.validate_transfer_evidence --directory tests/desktop-output/transfer-selection-v2
```

Повторная запись в каталог с существующим `protocol.json` запрещена, чтобы
не затереть предыдущие результаты. Для независимой новой выборки нужно менять
также `--seed-start`. В `results.json` записаны хеши исходников, все действия,
изменения весов, ошибки предсказания и отпечатки памяти; `protocol.json` создаётся
до первого испытания. Старые артефакты остались в `tests/desktop-output/transfer/`.

Регрессионный набор:

```powershell
python -B -m pytest -q -p no:cacheprovider tests/desktop/test_route_selection.py tests/desktop/test_transfer_experiment.py tests/desktop/test_goals.py tests/desktop/test_kernel.py tests/desktop/test_neural_learning.py tests/desktop/test_imagery.py tests/desktop/test_shared.py tests/concepts/test_shared_regression.py

```

Из `web/`:

```powershell
npm run build
node --test --test-isolation=none tests/bundle.test.mjs
```

отдельной проверки обученного обхода в JavaScript и завершения тестового
контроля: **20 passed, 1 deselected, 16 subtests passed** в целевом наборе
(`test_route_selection`, `test_transfer_experiment`, `test_goals`, без ранее
пройденного теста с временным каталогом). Всего проверено 75 различных Python-тестов.
JavaScript: **99 passed** и ещё **5 проверок сборок**. Сборка завершилась успешно.
Проверены преждевременное решение, равенство, пустые/нулевые сигналы, порог,
изменение весов и параметров, границы на циклическом графе, отсутствие изменений
памяти при выборе, Python/JS-паритет и сохранение навыков после перезапуска.

каталогами и подпроцессами успешно выполнен в разрешённом запуске вне sandbox.
Эксперимент выполнялся внутри sandbox, без действий в рабочих приложениях.

Самопроверка: повторяющийся выбор из двух исполнителей вынесен в общий модуль;
прежнее правило сохранено только в экспериментальном контроле; из исполнителей
удалены дублированные вычисления волн и ранний выбор по фиксированному отрыву.
