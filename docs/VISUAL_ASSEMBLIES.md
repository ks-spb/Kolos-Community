# Значок и подпись: обучение составного объекта

В режиме «Состояния и цели (ПК)» Колос может дополнить выученную команду
зрительным образом из значка, подписи и их взаимного расположения. Новые
признаки извлекаются из изображения Glaz. Для этого различения не используются
UI Automation, DOM, OCR или внешняя языковая модель.

Подсказки доступны прямо в программе: кнопка **Подсказки** в окне обучения и
пункт **Опыты и инструменты → Подсказки по зрительному обучению**, а также
команда `/visual-help` в терминале. В Neural Studio кнопки обучения значка и
подсказок также находятся в разделе **Учить / Обучение**. При выборе значка и существующего образа
окно объясняет следующий шаг. При неоднозначности терминал сообщает, где открыть
обучение, что показать и как продолжить удерживаемую цель.

## Как дообучить o1

1. Перезапустите Glaz после обновления кода. Выберите нужный монитор и включите захват.
2. Откройте **Опыты и инструменты → Обучить составной объект**.
3. Нажмите **Снимок через 3 с**, вернитесь на рабочий стол с нужной папкой.
4. В полученном снимке щёлкните по центру значка. Затем обведите рамкой его полную
   подпись. Бирюзовая рамка показывает выбранный контур, жёлтая — подпись.
5. Задайте имя образа, выберите команду `o1` и её объект (например, `glaz.56`).
   Подтвердите показ и дождитесь сообщения о сохранении.
6. Закройте окно обучения, переставьте папку и выполните `o1` обычным способом.
   Связанная с образом команда автоматически использует зрительный наблюдатель.

Если у команды несколько разных кликов по одному классу значков, первая версия
не привязывает их все к одной папке: требуется отдельная команда для этой цели.
Другие команды с тем же `glaz.56` не переименовываются.

Образ можно сохранить без команды, затем записать новую команду обычным способом
и добавить показ этого образа с привязкой к новой команде. Для записи без UIA
выберите **Опыты и инструменты → Зрительный режим без UI Automation** или введите
`/vision on`. В этом режиме содержимое текстовых полей не читается; для прежних
задач ввода предусмотрено `/vision off`.

## Другие виды и обрезанные подписи

Для того же объекта выберите существующий образ в первой строке диалога и
покажите дополнительный вид: подпись справа, другой шрифт, подсветку или масштаб.
Первый пример должен быть полным. При показе обрезанного вида отметьте сторону
обрезания; Колос запоминает реально видимую часть этого варианта. Общее чтение
новых слов и узнавание любого произвольного обрезания не заявляются.

Если у нескольких кандидатов видны одинаковые начала, Колос удерживает цель,
переходит в **«Нужна помощь»** и не выбирает по номеру, старым координатам или
положению курсора. Покажите более полный/различающий вид, закройте диалог и
нажмите **Пуск**. Уже подтверждённые действия не выполняются заново.
В связке CLICK → Enter после отправки клика выбранный экземпляр больше не
распознаётся заново: подсветка, изменение подписи и Glaz-ID не требуют помощи.
Смена окна, фокуса или доступности UIA после клика также не отменяет следующий
Enter: он продолжает уже выбранную связку. Явный стоп, сброс и отзыв разрешения
на ввод отменяют продолжение; пауза приостанавливает отправку. Повторный клик
автоматически не выполняется.

Изменения размера значка в пределах 0,5–2 от показанного размера допускаются
при поиске кандидатов; узнаваемость штрихов зависит от рендеринга. Для другого
оформления добавьте пример. Предел — 12 вариантов на образ, 240 подтверждённых
показов и прежний общий лимит 5000 узлов. Переполнение бюджета осмотра приводит
к запросу помощи, а не к выбору из неполного списка.
Перед сохранением проверяется лимит файла памяти 4 МБ; при превышении новый показ
не сохраняется, предыдущая память остаётся доступной.

## Что делает сеть

В общей памяти StateEngine добавлены ансамбли `visual_fragment`, `visual_part`,
`visual_relation`, `visual_variant`, `visual_object`, `visual_look`. Фрагменты
содержат локальные карты пиков; положение фрагментов и пустые участки не теряются.
Все части одного варианта относятся к одному текущему экземпляру.

Связи `visual_contains` и `visual_spatial` обязательны для сенсорного совпадения.
`visual_ground` связывает конкретный моторный шаг с образом.
`visual_attention` возбуждает осмотры разных подробностей. У осмотренных видов
тормозится повторный выбор внимания; равнозначные осмотры обслуживаются вместе.
Порог и отрыв действуют на кандидатов, а не на их ID.

I — внутренний запрос — накапливается отдельно от сенсорного свидетельства.
Текущая активация кандидата накапливается с прежним `decay`; исчезнувшее или
противоречащее свидетельство сразу перестаёт разрешать действие. Перед моторной
отправкой повторно рассматриваются все подробные варианты в новом кадре.
Нулевая обязательная связь блокирует подтверждение. Повторный подтверждённый
показ усиливает связи только показанного варианта; распознавание само по себе не
считается обучением. Накопленное возбуждение прежнего места не разрешает равенство
между одинаковыми кандидатами в текущем кадре.

Это инженерная модель обучаемых ансамблей и внимания, а не биофизическая модель
мозга. Распознавание знакомой надписи по штрихам не равнозначно чтению её смысла.

В окне **Нейроны → Зрение и внимание** показаны хранимые связи, текущие экземпляры,
сенсорные уровни, конкуренция и осмотры. Это проекция расчёта работающего ядра.
Просмотр не управляет мышью. Окна Glaz, включая снимок в диалоге обучения,
исключаются из зрительных кандидатов.

## Память и проверки

При загрузке памяти v2 создаётся `memory-v2-<время>.json`, затем сохраняется v3.
Команды, веса и журнал неподтверждённого действия сохраняются. Координаты,
возбуждения, привязки экземпляров и незаконченные осмотры после перезапуска не
возобновляются. Повреждённый граф не перезаписывается.

Команды проверок из корня проекта:

```powershell
python -m unittest discover -s tests/perception -v
python -m unittest discover -s tests/desktop -q
python -m unittest discover -s tests -p 'test_glaz*.py' -q
$env:KOLOS_VISUAL_UI_SMOKE='1'
python -m unittest discover -s tests/perception -p test_teacher.py -v
```

Последний тест открывает только собственное окно обучения и передаёт ему
синтетические события; физическая мышь не используется. Изображения и реальный
детектор проверяются отдельно от работы в приложениях пользователя.

Практическая приёмка: три одинаковых значка с разными подписями, перестановка
всех трёх, другой значок на старом месте, затем такой же опыт с вкладками.
Проверить отдельный отказ при одинаковых обрезанных подписях. Эти действия
на рабочем столе и в браузере не следует объявлять пройденными по модельным тестам.
