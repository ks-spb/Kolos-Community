# План проверок пилота Колоса на выгрузках акций WB

GStack Autoplan, инженерное ревью, 27 ноября 2026 года. Реализация от `main` в Kolos-Community. [План реализации](kolos-wb-promotion-export-pilot.md)

## Входы и эталон

Использовать четыре обезличенных манифеста с непересекающимися ID акций. Зафиксировать момент проверки и ожидаемые ID. Эталонные ответы составить вручную и хранить отдельно от данных, передаваемых в Codex. Свежая запись относится к тому же дню в Москве и имеет время не позже момента проверки.

| Манифест | Состав | Эталон |
|---|---|---|
| A. Исходная версия | Ожидаемые акции с нулём, одной и двумя свежими строками | Исходное правило считает полной акцию с одной строкой. Повторы и ошибки совпадают со штатной квитанцией WB. |
| B. Первый случай учебной версии | Ожидаемые акции с нулём и одной свежей строкой. Отдельная инструкция требует две | По обеим недостача. Предложенный порог 3 даст те же ответы на этом входе, но провалится на C. |
| C. Повтор | Другие ID. От нуля до трёх свежих строк. Отдельные акции с двумя свежими и просроченной либо неудачной попыткой. Одна неожиданная акция | 0 и 1 — недостача, 2 — полнота, 3 — излишек. Просроченная и неудачная попытки имеют отдельные признаки. Неожиданная акция отмечается отдельно. |
| D. Регрессия исходной версии | Другие ID с полным результатом по v1, ошибочной и просроченной попытками | Исходный смысл `missing_or_ambiguous` и `duplicate_ids` сохраняется, в том числе при учёте повторов среди всех попыток. |

## Действия пользователя и критические пути

| Проверка | Вид | Критерий |
|---|---|---|
| `--help` и `local` из PowerShell с Python, без Codex и рабочей `.local-data` | E2E Windows | Понятны режимы и артефакты. На пути с пробелами и UTF-8 создаётся серия, вывод совпадает с эталоном. Время первого результата записано. |
| Подготовка `compare` в чистой копии Kolos-Community | Интеграционный Windows | Явный путь к локальному `memory.json` даёт отдельно собранный комплект v1 из памяти и рецепта. A и D проходят эталон. Отсутствующий или непригодный исходный граф останавливает прогон до выбора адаптера. |
| Чтение A, урок на B и сохранение, чтение C после перезапуска, регрессия D | E2E с тестовым ответом | На B ровно один вызов имитатора, на остальных этапах ни одного запуска адаптера. PID повтора отличается, новый ID запуска и вход, отпечатки совпадают с уроком. C работает с отключёнными внешним процессом и сетью в тестовой ветке. |
| Отказ от кандидата, похожего на правильный | Интеграционный | Кандидат с порогом 3 проходит схему и B, проваливает закрытый C. Версия недоступна к чтению, исходная остаётся рабочей. |
| Чтение сохранённого порога | Интеграционный | Проверенный снимок с другим допустимым порогом из отдельного контрольного опыта меняет результат. Подмена правила или исходного снимка при верном правиле отклоняется. |
| `compare` с фактическим Codex после локальной приёмки | Модельная оценка | Успешная серия содержит один внешний запуск на урок, ноль на A/C/D и четыре отдельных прямых запуска. Все ответы проходят один эталон. Полный цикл и B+C получают отдельные итоги. |
| Ошибка процесса или неверная модельная классификация | Интеграционный и контроль A/B | Квитанции пройденных этапов сохранены. Оставшиеся этапы явно помечены как пропущенные. Расход попытки сохранён при наличии. Явный статус и ненулевой выход для несопоставимой серии. |

## Граничные случаи

| Ветвь | Проверки |
|---|---|
| Вход | Отсутствующий файл или версия, неподдерживаемая версия, пустой валидный календарь, ожидаемая акция без записей, неверная кодировка, слишком большой файл, повтор JSON-ключа, `null` или `bool` на месте числа, несовпадение или дубль ожидаемых ID. Невалидный вход обрабатывается до модели. |
| Время | Граница полуночи МСК, корректный отличный часовой пояс, строка без пояса, время строки позже момента проверки. Фиксированный момент одинаков у обеих веток. |
| Модель | Прерванный процесс, таймаут с частичным stdout, отсутствие запуска, отказ, неправильная форма JSON, вызов инструмента, отсутствующий или повторяющийся `usage`. При повреждённой последней строке полные предыдущие события сохраняют значение. |
| Списание | Целые неотрицательные счётчики, кэш не больше входа, частичный учёт, отклонённый ответ с известным расходом, ноль только при подтверждённом отсутствии вызова, `не запускался` для пропущенного этапа. |
| Память | Отсутствующий пакет, неправильная версия, неверный хеш, повреждённый или слишком большой снимок, прерванная запись до публикации, блокировка замены Windows. Неудачный пакет не виден читателю. |
| Параллельный запуск | Два процесса пытаются обучить одну версию в одной серии. Внешний процесс открывает только один владелец, второй видит конфликт. Новый процесс может выполнить исходную версию. |
| Изоляция | Новая серия использует свою копию. Отпечатки исходной памяти, штатных снимков и результатов v1/Ozon совпадают до и после. Пробный запуск без отправки данных проверяет условия изоляции CLI. |

## Наборы для запуска

- Существующие `test_automation_shadow.py` и `test_programming_synthesis.py` через pytest. Они покрывают штатный WB, Ozon, текущий исполнитель и разбор ответа. На этапе ревью эти два файла дали 19 прошедших тестов. Повторить их на актуальной целевой ветке.
- Новый набор `test_wb_promotion_pilot.py`. Локальные тесты и два процесса работают без внешнего аккаунта и входят в обычный запуск проверок. Во всех ветвях запуска модели используется контролируемый тестовый ответ или явный запрет адаптера.
- Живой `compare` запускается отдельной командой после локального прохода и проверки профиля. Результат с неполным `usage` или неверным ответом сохраняется как диагностический. Сводка экономии допустима только при полной парности, правильных ответах и полном расходе.
