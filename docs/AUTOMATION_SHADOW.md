# Колос в автоматических задачах Codex

## Локальный пилот на выгрузках акций WB

В корне репозитория запустите:

```powershell
py -3 -B -m kolos_states.wb_promotion_pilot local
```

Команда использует четыре синтетических манифеста и тестовый ответ вместо Codex. Она проверяет исходное правило, сохраняет учебное, применяет его на новом входе из второго процесса и повторяет проверку исходного правила. В отчёте второй процесс подтверждается новым PID и идентификатором запуска, совпавшими отпечатками и нулём вызовов Codex.

Для живого сравнения нужны установленный Codex CLI, доступная в аккаунте модель и локальный `memory.json` исходного графа. Укажите модель и путь к файлу через переменные PowerShell:

```powershell
$wbPilotModel = Read-Host 'Имя модели Codex'
$wbPilotBase = Read-Host 'Путь к исходному memory.json'
py -3 -B -m kolos_states.wb_promotion_pilot compare --model $wbPilotModel --base-snapshot $wbPilotBase
```

Успешное сравнение делает один запуск Codex для урока и четыре отдельных запуска для прямых ответов на те же манифесты. Модель получает синтетический манифест и инструкцию. Эталонные ответы и память читаются локально. Рабочие правила, расписания и кабинеты не участвуют в пилоте.

`local` сохраняет результат в `tests/desktop-output/wb-promotion-pilot/run-*/`. `compare` хранит отчёт и копию снимка в `.local-data/wb-promotion-pilot/run-*/`, вне каталога артефактов CI. В stdout возвращается JSON со статусом и `report_path`. В квитанции есть результаты по манифестам A–D, итог всего цикла и итог пары «урок и повтор». Кэшированные токены входят в общий вход. Пропущенный шаг и неизвестный `usage` отличимы от нулевого расхода. При отказе откройте `report.json` и соответствующий `attempt.json`. Для повторной проверки создайте новую серию той же командой.

## Текущая автоматизация

Существующий триггер Codex запускает задачу в её чате. Колос выполняет шаг из реестра `PROFILES`, а ChatGPT сравнивает результат с источником и продолжает обычную процедуру. Обе части сохраняют раздельные отчёты. Колос использует неизменяемый снимок памяти.

## Контракт запуска

Из проекта Колоса выполните `python -B -m kolos_states.automation_shadow run --output-root <папка задачи>/outputs/kolos-shadow`. Передайте UTF-8 JSON через stdin с `automation_id`, `run_id` и `input`. Отчёт возвращается в stdout и сохраняется в `<output-root>/<automation_id>/<run_id>/handoff.json`. Допустимые результаты `completed`, `partial`, `skipped`, `failed`. Профиль без навыка получает `skipped` и причину. Один и тот же ID и вход возвращают прежний отчёт. При конфликте входов задача продолжает штатный сценарий.

- Для XWAY `input` содержит фиксированную `task` и два `observations` из точных запросов коннектора. Локальный файл `.local-data/automation-shadow/xway-profile.json` связывает `task` с `memory_run` учебного прогона. Сценарий использует прежний исполнитель чтения кампании.
- Для акций WB передайте `manifest`, `observed_at` и `source_ref`. Добавьте `expected_ids`, если точный список есть в текущем календаре. В отчёте различаются отсутствующие, повторные, неудачные и устаревшие выгрузки.
- Для Ozon передайте `account_id`, `date_from`, `date_to`, `missing_dates`, `missing_ad_dates`, `observed_at`, `source_ref` и `cost_rows`. В каждой строке себестоимости берутся поля `marketplace_sku` и `roi_cost_incomplete` из обычного отчёта. Вход относится к последней полной неделе МСК. В отчёт Колоса попадают только ключи пробелов и служебные счётчики.

Для обучения проверки полноты предназначена команда `python -B -m kolos_states.automation_coverage`. Она сохраняет отдельно исходную и обученную память в `.local-data/programming-lab/snapshots/automation-coverage-v1`. Рабочий запуск читает только уже обученный снимок.

## Проверка и возврат инструкции

Сверьте отчёт с источником и передайте тем же способом команду `review` с `automation_id`, `run_id`, исходным `input_sha256`, `verdict` и массивами строк `confirmed`, `corrected`, `unknown`, `sources`. Результат сохраняется рядом в `review.json`. Доступные вердикты `confirmed`, `corrected`, `not_confirmed` и `not_needed`. В обычный итог добавляется краткая сверка. Тихий запуск создаёт уведомление только при исключении согласно действующей политике задачи.

Для отката верните прежнюю инструкцию конкретной задачи штатным инструментом расписаний Codex. Копии инструкций перед подключением лежат в `tests/desktop-output/automation-rollout-20261127/original`. Сверьте название, статус, периодичность, чат и настройку уведомлений после отката.
