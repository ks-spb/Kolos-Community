# Колос, скрипт и модель со скиллом: локальный replay кластеров

**Эксперимент выполнен.** Колос и скрипт исполняют знакомую процедуру без LLM.
На этом контракте обычный скрипт быстрее; преимущество Колоса перед ним не выявлено.

### Что подтверждено

1. Для знакомой типизированной процедуры Колос способен обходиться без LLM
   на исполнении. Выученная связь причинно нужна: её отключение останавливает
   соответствующий регрессионный тест.
2. Ручной скрипт даёт тот же результат с нулём модельных токенов и меньшей
   задержкой. Устранение LLM-вызовов само по себе не доказывает преимущество
   обучаемой архитектуры перед обычной автоматизацией.
3. На данном наборе преимущество модели в обработке помех не проявилось:
   общие host-проверки и два локальных исполнителя дали те же безопасные исходы.
4. Проверка сравнивает исполнение уже выбранного действия. Выбор гипотезы,
   экономику рекламы, адаптацию к новой странице и стоимость изменения сценария
   она не измеряет. Это следующие вопросы для оценки пользы обучаемой памяти.

Кэш в основном прогоне не использовался. Денежная экономия или снижение лимита
подписки в процентах не выводятся из этих токенов. Результаты скорости относятся
к локальному хосту: в настоящем кабинете добавятся сетевые и браузерные задержки.

## Что именно испытывается

Это **локальная реконструкция контракта операции по сохранённым before/after**,
а не повтор браузерной сессии или проверка живого интерфейса XWAY. Стенд проверяет,
можно ли выполнять знакомую типизированную процедуру с меньшим участием LLM.
Выбор рекламной гипотезы, экономический эффект и реальная скорость кабинета
в этот опыт не входят.

Исходник — один прочитанный снимок `wb_analitika/data/product_manager/state.json`.
Импортированы только `verified` операции `advertising.cluster.set_excluded`
с совпадающими identity/campaign/query и наблюдаемым переходом excluded к заданному
значению. Всего **6 операций: 5 возвратов и 1 исключение**. Неисполненные предложения
и неуспешная попытка не превращались в подтверждённые примеры.

Для разработки и обучения использован возврат из ранее рассмотренного чата
«WB · демонстрационный товар · Менеджер». Остальные **5 операций** отложены: четыре возврата
и одно исключение. Демонстрация исключения Колосу не показывалась.

Снимок, хеш исходника и полные входы остаются в локальном, игнорируемом Git
каталоге результатов. Техническая сводка не содержит исходных товарных данных.

## Одинаковый контракт

Доступны только локальные `read`, `write`, `activate` над явно наблюдаемыми ролями:

1. Прочитать запрошенный excluded в рабочий слот.
2. Проверить условия: точные товар/кампания/кластер, имитированное разрешение,
   однозначная форма, отсутствие уже применённого результата.
3. Зарезервировать попытку.
4. Перенести прочитанное значение в черновик.
5. Сохранить один раз.
6. Прочитать сохранённое состояние заново.
7. Проверить соответствие результата запросу.
8. Зафиксировать проверенный результат.

Хост независимо проверяет допустимость действий и итог. Черновик не считается
изменением рекламы; отправка Save не считается подтверждением результата.
При неизвестном исходе Save прогон остаётся pending, повтор запрещён.

Прежние реальные разрешения не дают полномочий этому стенду: используется только
локальный флаг имитированного разрешения. Ни старые, ни новые реальные proposals
не создавались и не исполнялись.

## Три варианта

| Вариант | Где задаётся процедура | Работа модели при проверке |
|---|---|---|
| Скрипт | Вручную заданная параметризованная последовательность | Нет |
| Колос | Один показ через существующий `BrowserEpisodeBridge` и `StateEngine.learn_episode` | Нет |
| Модель + skill | Реальный ответ `gpt-6.1-sol` через установленный provider SDK Hermes | Один пакетный план на случай |

Колос использует существующие связи `episode_next`, `episode_produces`, `episode_value`
и роли. Значение новой задачи читается заново; runtime ID и порядок объектов
меняются. В каждой попытке загружается JSON выученной памяти, а рабочие значения
не наследуются. Это включает стоимость загрузки памяти в измерение исполнения.
Тест с отключением выученной связи останавливает именно Колос; скрытого перехода
к скрипту нет. Отдельный тест проверяет загрузку в новом интерпретаторе.

Учебная последовательность восстановлена и показана программно по контракту
операции. Автоматическое чтение произвольного SKILL.md и самостоятельная генерация
адаптера Колосом здесь не реализованы. Время восьми учебных действий измеряется,
но человеческий труд над адаптером, скриптом, skill и разметкой не оценён.

Модель получает компактный [skill](../kolos_states/cluster_replay/skill.md),
наблюдаемые роли, условия и ожидаемый эффект. Ей разрешён весь план одним ответом,
а не обязательное рассуждение перед каждым полем. Температура 0, максимум16
локальных операций, повторных запросов ради исправления ответа нет.
Полный исторический контекст менеджера, консилиум и журналы в промпт не включены:
это оптимизированный модельный контроль, а не цена полного прохода рабочего чата.

## Защита и приватность

- Replay-хост блокирует сетевые connect/create_connection; кода обращения к XWAY,
  WB, Google, браузеру или денежному реестру в нём нет.
- Модель работает в отдельном процессе, получает `tools=[]` и возвращает только JSON.
  Хост принимает закрытый список операций; Python, shell, URL и произвольные
  команды из ответа исполнить невозможно.
- SDK разрешены только model-host `chatgpt.com`/`api.openai.com`. Реальные рабочие
  Hermes-сеансы не продолжаются, профили/установка/зависимости не меняются.
- В каждом исходящем запросе товар/магазин/кампания/кластер заменены на demo-*.
  Исходные nmID, артикулы, query, proposal_id, пути и настройки не отправляются.
  Равенство/неравенство scope сохраняется. Связь с исходными кейсами есть только
  в локальных артефактах; post-run validator повторно проверяет каждый запрос.
- Первоначальный запуск с возможной передачей бизнес-данных был отклонён
  автоматической проверкой до вызова модели. После полного обезличивания безопасный
  вариант разрешён. В установке Hermes найден особый запуск Python; использованы
  только уже установленные зависимости без обновления или ремонта приложения.

## Выборка и измерения

На каждую отложенную операцию приходится девять вариантов:

- обычная операция;
- несовпадающая identity;
- отсутствие разрешения;
- результат уже применён;
- неоднозначное поле;
- устаревшее чтение результата;
- Save не дал эффекта;
- квитанция Save потеряна;
- scope изменился после резервирования попытки.

Только базовые before/after взяты из реестра. Все помехи — явно синтетические
модификации локального состояния. Всего **45 испытаний на вариант, 135 в сумме**.
Протокол и хеши кода/корпуса фиксируются до отложенных прогонов. Используется
смена порядка исполнителей между исходными кейсами. Выборка мала; один ответ
модели на случай не измеряет её стохастическую надёжность.

Основные метрики: завершение5 обычных задач, правильный исход40 помех,
ложный успех, недопустимые операции, повтор Save, количество обращений к модели,
входные/выходные/кэшированные токены и полное время. Кэш — часть входа и второй
раз к нему не прибавляется. Медиана скорости показывается отдельно для обычных
задач. В неё входит весь ответ модели и локальное исполнение; старт SDK отдельно.
Фактическая стоимость аккаунта/подписки неизвестна, денежная экономия не вычисляется.

## Воспроизведение

Из корня Колоса, всегда в новом каталоге вывода:

```powershell
python -X utf8 -B -m kolos_states.cluster_replay --output tests/desktop-output/cluster-replay-new --frozen-corpus tests/desktop-output/cluster-replay-20261111/corpus.json --with-model
python -X utf8 -B -m tests.desktop.validate_cluster_replay --directory tests/desktop-output/cluster-replay-new
```

Без `--with-model` выполняются два локальных варианта без запросов провайдеру.
Без `--frozen-corpus` импортируется текущий исходник через `--source`; это уже
другая выборка, если реестр изменился. Для модели нужен установленный Hermes SDK
и штатная авторизация провайдера. Команда не запускает updater или gateway.

```powershell
python -B -m pytest -q -p no:cacheprovider tests/desktop/test_cluster_replay.py tests/desktop/test_episodes.py tests/desktop/test_episode_boundaries.py tests/desktop/test_episode_browser.py
```

Регрессии: **48 passed, 65 subtests passed**. Проверены перенос значения в обратное
действие, новые runtime ID, порча графа, сбои, независимый oracle, запрет произвольных
команд, блокировка сети, отсутствие бизнес-строк в промптах и новый процесс.
Для старых тестов с временными каталогами Windows использован разрешённый запуск
вне sandbox.

Самопроверка: хост, импорт доказательств, три стратегии, SDK-транспорт, агрегация
и CLI разделены по модулям; общее исполнение не дублируется. Учебная и рабочая
память разделены. Рабочее ядро Колоса и бизнес-код WB не изменены.
