# Этап 1 — полноценный рабочий эпизод и роли

Ветка: `feature/browser-graph-lab`. Исходное состояние: `e3955a980982af6f630f23d0d83a86f6e4cb965f`.

**Область приёмки — E13 «Ученик: два поля»: новая строка и новая компоновка.**
E14 в таблице означает перенос на другой ПК и относится к этапу 3; здесь он не закрывается.

## План, зафиксированный перед реализацией

1. Сохранить прежние пути выполнения 1–12 и их математические правила.
2. Добавить наблюдаемые объекты и роли по устойчивым описателям вместо координат и локальных ID.
3. Записывать порядок общих операций чтения, ввода и активации из демонстрации, вместе со связями значений.
4. Хранить значения текущей попытки отдельно; подтверждать ввод и сохранение наблюдениями среды, сохранять источник.
5. Подключить к тому же `StateEngine`, хранилищу и интерфейсу Glaz.
6. Проверить новые строки, компоновки, несколько полей, перезапуск, отказы и прежние возможности до изменения статуса.

## Критерии проверки

E13 должен прочитать неизвестное заранее значение, перенести его в другое поле,
сохранить результат и оставить источник неизменным. Повторение — с новым значением,
другим расположением и новыми локальными ID, без нового показа.

Дополнительные проверки: два источника/получателя, несколько блоков ввода с
последующими действиями, Unicode, пробелы, пустые строки, неоднозначные/исчезнувшие
объекты, нечитаемые поля, ошибочное сохранение, повреждение источника, чужие и
повторные квитанции, тайм-аут, F9, пауза, отсутствие разрешения, восстановление памяти.
Удаление выученной связи должно останавливать эпизод, а не включать скрытый маршрут.
Возможности 1–12 проверяются на той же памяти до/после нового обучения, в разных
порядках и после сохранения/восстановления.

## Реализация

### Память и роли

`kolos_states/episodes.py` добавляет к общей памяти вершины команды, роли, шага,
слота значения и завершения. Связи `episode_next`, `episode_binds`,
`episode_produces`, `episode_value` и `episode_effect` сохраняют показанный порядок,
привязку объектов, поток значений и наблюдаемые результаты.

Объект сопоставляется по `(kind, name, scope, automation_id)`. Геометрия, порядок
перечисления, текущая строка и runtime ID не входят в описатель роли. Для исполнения
нужен ровно один подходящий доступный объект. Дубликат или отсутствие — остановка,
а не выбор ближайшего поля. Для Windows `scope` включает класс, AutomationId и
заголовок выбранного окна; изменение этих признаков требует нового согласования,
оно не маскируется как уже подтверждённый перенос.

Последовательность возникает из демонстрации, а не из названия задачи. В ядре нет
встроенного маршрута «Source → Target → Save», разбора суммы или подстановки
значения из фразы. Запуск распознаёт **точную выученную фразу**; содержимое читается
из среды заново. Временные слоты очищаются при завершении/Reset и не возобновляются
из сохранённого сеанса.

### Наблюдение и действие

`episode_desktop.py` читает доступные поля выбранного Windows-окна через UI
Automation. Общие инженерные примитивы — чтение значения, замена текста через
ValuePattern и активация кнопки через InvokePattern. Это не утверждение, что агент
сам открыл эти моторные операции. Здесь не используются OCR, LLM, буфер обмена,
заданные координаты, повышенные права или готовые сценарии сайтов.

После действия нужны два свежих согласованных наблюдения. Ядро повторно проверяет
квитанцию: тот же сеанс/запрос/объект, точное значение, неизменность защищённых
источников и отсутствие непоказанных изменений других полей. Возврат функции
SetValue/Invoke сам по себе не считается успехом. Сохранение подтверждается
наблюдаемым эффектом, выученным из показа.

После отправки запрос не повторяется автоматически даже при исключении или
тайм-ауте. Поздняя квитанция не возобновляет остановленную попытку. Нужно осмотреть
форму и явно выполнить Reset. Разрешение Glaz, F9 и пауза проверяются до действий и
во время ожидания результата. Работа ограничена явно выбранным окном.

### Запись, хранение и интерфейс

`EpisodeRecorder` записывает отдельные операции, выбранные пользователем. Ввод
ссылается на ранее прочитанный слот (`v0`, `v1` и т. д.). Неоднозначное обучение
отклоняется атомарно: половина графа не остаётся в памяти.

Новый диалог `Glaz/episode_dialog.py` отправляет команды существующему States-
подпроцессу через прежний терминал. `episode_console.py` использует тот же экземпляр
`StateEngine` и тот же `Store`, а не отдельный демонстрационный движок.
Хранилище восстанавливает записи `learningLog` в исходном порядке и поддерживает
старые записи. Ролевые вершины и активные значения видны в диагностике нейронов.

**Приватность:** журнал обучения и квитанции сохраняют наблюдавшиеся значения и
локальные ID для аудита. Очистка временных слотов не удаляет исторические записи.
Не обучайте эпизоды на паролях или важных личных данных. Это ещё не очищенный от
локальных сведений переносимый пакет навыка этапа 3.

## Как проверить через Glaz

Один раз установить зависимости через `install_states.bat`, затем запустить
обычный `run_main.bat`. Выбрать **«Состояния и цели (ПК)» → «Опыты и инструменты» →
«Рабочий эпизод и роли»**. Режим Legacy по умолчанию и прежние кнопки остаются.

1. Нажать «Тестовое окно». Обновить список «Окна», выбрать `Kolos working episode`
   и нажать «Прочитать». В таблице появятся поля и кнопка Save.
2. В главном Glaz включить «Разрешить управление ПК». В диалоге оставить фразу
   «Перенеси содержимое поля и сохрани» и нажать «Начать показ».
3. Выбрать Source 1 → «Прочитать → значение». После подтверждения выбрать Target 1
   и слот `v0` → «Ввести значение». Затем Save → «Активировать» → «Сохранить показ».
4. В тестовом окне изменить Source 1 на другую строку. В диалоге нажать
   «Выполнить фразу». Target 1 и Saved 1 должны получить новую строку, Source 1 —
   сохранить её, Unrelated — остаться без изменений.
5. Для другой компоновки открыть новое одноимённое тестовое окно командой ниже,
   выбрать его в диалоге и прочитать. Выполнить **ту же фразу без повторного показа**.

```powershell
python -m kolos_states.episode_pad --source "Новая строка 6143" --layout 1
```

Закрывайте только созданные тестовые окна. Старые сочетания `3`/`5` записывают
прежний формат клавиш; для нескольких блоков ввода используется новый диалог.
Новая попытка запускается кнопкой «Выполнить фразу», а не старой кнопкой «Пуск».

## Воспроизводимые проверки

Модельный E13 без управления ОС:

```powershell
python -m kolos_states.episode_experiment --evidence tests/desktop-output/stage1-model.json
python -m unittest discover -s tests/desktop -v
```

Все дополнительные Windows-проверки создают собственные одноразовые окна:

```powershell
$env:KOLOS_WINDOWS_SMOKE = '1'
$env:KOLOS_INLINE_GUI_SMOKE = '1'
$env:KOLOS_STUDIO_GUI_SMOKE = '1'
$env:KOLOS_EPISODE_WINDOWS_SMOKE = '1'
$env:PYTHONIOENCODING = 'utf-8'
python -m unittest discover -s tests/desktop -v
```

Старый код и браузерная регрессия (нужны pytest, PyVis, Node.js, Playwright и Chromium):

```powershell
python -m pytest tests --ignore=tests/desktop -q
cd web
npm ci
npm run check
npm test
npm run test:acceptance
npm run test:browser
npm run test:acceptance:browser
```

В существующий процесс GitHub Actions добавлены модельный E13, реальные Windows-проверки и
проверка нового диалога. Результаты локального запуска не подменяют статус
последующего запуска CI на GitHub.

## Совместимость, найденная регрессией

При проверке Windows исправлены существовавшие препятствия запуска, не правила
нейронных движков: упаковка однофайловых браузерных приложений с CRLF; выбор
`python`/`python3` в SQL-reference тесте; явное UTF-8-чтение экспортов в двух
браузерных тестах; кавычки одного диагностического f-string для Python 3.11.
Для упаковки добавлены отдельные проверки LF/CRLF и разбора всех трёх HTML-файлов.

## Границы этапа

Поддержаны устойчиво описанные доступные поля и кнопки выбранного окна. Смена
заголовков/меток, структурное появление новых страниц, нестандартные недоступные
контролы, перетаскивание и произвольные приложения не объявляются поддержанными.
Нужен наблюдаемый эффект активации: если Save ничего не меняет, подтверждения нет,
даже когда желаемое значение уже находилось в Saved. Это консервативный отказ.
Многострочные значения проверены на модели; настоящая учебная форма содержит
однострочные EDIT-контролы.

Подтверждены повторение эпизода, новые значения и новая геометрия на проверенной
форме. Не утверждаются перенос на второй ПК (E14), выполнение любой новой задачи,
самостоятельное построение плана или достижение AGI. Следующий этап дорожной карты
— внешний учитель/советник с независимым подтверждением результата средой.
